# Exactory 0.72.2

This release makes a command derive each review request of an assignment once and share it. Within one command,
request selection and attempt authentication now use the same derived request. The requests, packets, reports,
obligations and refusals do not change. The release follows 0.72.1. The work is recorded in
`misc/harness-improvement/20261103225743-post-gate-rebuilds-every-review-request` of the exactory repository.

## Why

Measured on 2026-11-03 on a copy of a problem record at store revision 1294, on the code of 0.71.7:

- The record holds 141 review assignments and 149 review attempts. Each of its 32 result packets is about 7.5 MB.
- One `exactory-research status --summary` took 1,106 seconds on Python 3.9.6. One `review-assignment` of a new
  result turn took about 33 minutes.
- In an instrumented run on Python 3.12.8, one evaluation called `review_transport.request_body` 1,214 times on 102
  distinct inputs. 45 of these inputs were derived 11 to 37 times each. The calls took 1,134 of the 1,229 seconds of
  the evaluation.
- 673 derivations came from misses of the per-assignment memo of `build_assignment_request`. The other 541 came from
  `authenticate_provenance`, which did not use that memo. The memo missed because every optional value shares one
  LRU of 64 MiB: the retained bytes reached the whole budget, and the evaluation evicted 14,522 entries.

The code of this path is the same in 0.72.1. On the same copy, `exactory-research status` with 0.72.1 took 1,409
seconds on Python 3.12.8.

## What changed

- Request reuse. The new module `research_harness/review_request_evaluation.py` derives a text request through the
  unchanged `review_transport.request_body` and keeps it in the evaluation of the command. The key hashes the complete
  route, prompt, packet and ordered history, and adds the fit order and the local input limit. A recorded digest never
  replaces a value in the key. The module gives the candidates of the current and the earlier fit orders lazily, in
  the same order and with the same duplicate rule as the pinned `list_built_requests`.
- Selection and authentication. `build_assignment_request` and `authenticate_provenance` both use the module. The
  per-assignment memo of `build_assignment_request` is removed. Authentication still compares each recorded request
  in full with the built requests and runs every other check.
- Retention. A kept request is exact compressed JSON (`zlib` level 6). Requests have their own LRU of at most half of
  the evaluation budget (64 MiB by default). Other values use the space that requests leave free, and they do not
  evict requests. A request that is too large, or that does not round-trip exactly as JSON, is returned without
  retention. Nothing outlives the command.
- One evaluation per check. The preparation of `value-review` and the refusal check that follows a `review-run` pass
  one evaluation through all their checks, so these checks share the kept requests.
- Diagnostics. For a problem workspace, `status --counters` and `status --summary` now report `evaluation`, as they
  do for other workspaces: the counters, the elapsed time and the retention, with `request_bytes` and
  `request_entries`.

A visual route still builds its request on every call, because the build checks the current emitter bytes. A staged
review builds and checks its frozen request on every call. No route-pinned module changed, so the eleven pinned files
keep their hashes and every route keeps its pin.

## Upgrade

No record migration is necessary. Stored assignments, attempts and requests authenticate as before.

## Checks

The new work-count tests failed on 0.72.1 and pass after the change. Counted calls of `review_transport.request_body`:

| Test | 0.72.1 | 0.72.2 |
|---|---:|---:|
| One assignment, built and authenticated twice | 3 | 1 |
| The same after streaming more than the budget | 6 | 1 |
| Twelve large assignments, two passes | 96 | 12 |
| A warm parts v2 series, verified and read again | 5 | 0 |

`tests/test_review_request_parity.py` replays stored fixture builders: ordinary reviews, native math, result parts v1
and v2, openness chains v4 and v5, the 0.69.18 result history, a recorded earlier-fit request and the Claude and
framed Codex routes, with incomplete, failed, contaminated, corrupted, forged and refused cases. It compares the full
status and gate reports, assignment states, attempt selection, refusal details, authentication results, packet bytes
and request bytes with values frozen from a clean export of 0.72.1 (`ceb050b`). Its 22 tests pass before and after
the change on Python 3.12.8 and 3.9.6.

GPT 6 Astra at xhigh designed the change. The full suite, CI on every supported version, an independent code review
and a measurement on the record copy run after the pull request opens.
