# Exactory 0.71.8

This patch makes the file guard's discovery checks treat `ENAMETOOLONG` as absence. An overlong pathname no longer causes a controller-discovery recovery denial, while other unexpected check failures still deny the tool call.

## Why

Versions 0.71.4 and 0.71.5 handled overlong paths in the outer file guard, but controller discovery still raised while probing `.search/tree.json` or `.exactory/math-search.json`. A single-line Bash word or a Write or Edit path could reach that earlier failure. A whole pathname can exceed the filesystem limit even when every component is short.

## What changed

`hooks/math_search.py` adds `errno.ENAMETOOLONG` to the existing absence policy in `_read_mode`. Its four status helpers return False for that error in controller discovery, workspace discovery and output-view discovery. Ancestor and remaining-target checks continue, and permission errors and other unexpected failures still propagate to the existing denials.

The existing protections for harness-owned files, discovery pointers and generated output folders remain. There are no record, route, stored contract or pinned module changes. The hooks are outside the controller digest.

## Upgrade

No record migration is necessary. Start a new Claude Code session after updating; running sessions retain the hook version loaded at startup.

## Checks

Before the fix, the overlong-path regression selection fails on Python 3.9.6, 3.12.8 and 3.14.6: nine tests produce 13 failures and eight errors on each interpreter. Raw `os.stat` confirms `ENAMETOOLONG` for both the component-length and whole-path-length fixtures.

After the fix, all nine overlong-path tests and the mocked `PermissionError` test pass separately on all three interpreters. The full hook modules (72 and 55 tests), manifest tests (eight), research-guidance tests (nine) and Codex tests (30) pass on each interpreter, with no skips. The regressions cover real managed-tree discovery, later owned-file words and batch targets, while the existing heredoc, owned-file, discovery-pointer and generated-output protections remain. `codex/generate.py --check` and `git diff --check` pass.
