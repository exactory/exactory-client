# Exactory 0.34.2

Both plugin manifests identify version `0.34.2`.

## Fixes

- A reserved mathematical move can journal a validated problem refinement while
  retaining the admitted claim, original reservation, and budget. The intent
  preserves both problem snapshots and the exact journal line. Older pending
  reservations can supply the original problem value with `--problem-before`.
- Normal journal writes and recovery hold the same ownership lock through
  acknowledgment. Interrupted appends are validated and applied at most once.
  Recovery rejects changed problem values and conflicting journal artifacts.
- A narrowly scoped operator recovery can abandon an interrupted initial legacy
  rank after independent review of its exact source, incident and current
  snapshot. It preserves the original history and does not record a successful
  rank, grant proof credit, or reset usage.
- Invalid laboratory stages now have consistent validation diagnostics on
  Python 3.9 and 3.12, without weakening the accepted-stage checks.

See the [journal transition contract](../../skills/math-solver/harness/JOURNAL_TRANSITIONS.md)
and [operator rank recovery contract](../../skills/math-solver/harness/RANK_RECOVERY.md)
before recovering an existing attack. Neither path permits ambiguous recovery.

## Compatibility and upgrade

This version reads existing reservations and unchanged journal intents. Version
0.34.1 cannot replay intents with the new problem-transition payload. Upgrade all
writers of a research root before recording a transition. Do not edit an installed
cache or run old and new plugin processes against the same root.

For Claude Code:

```sh
claude plugin marketplace update exactory-ai
claude plugin update exactory@exactory-ai
claude plugin list --json
```

For Codex:

```sh
codex plugin marketplace upgrade exactory-ai
codex plugin add exactory@exactory-ai --json
codex plugin list --marketplace exactory-ai --json
```

Preserve the existing installation scope. Confirm that the returned version
and installed manifest identify `0.34.2`, then start a new session and review
and trust changed hooks through the host's supported flow. Updating does not
resume paused research, adopt attacks, or reset budgets. The existing-attack
and verification boundaries in the [0.34.0 notes](0.34.0.md) still apply.

## Publication

The marketplace catalogs use the client repository without a pinned tag. Merging
source, publishing a GitHub Release, and updating an existing installation are
separate operations. These notes do not assert that a tag or GitHub Release has
been published.
