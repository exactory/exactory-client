# Exactory 0.59.0

This release changes result coverage to require the bound search records
without requiring the bodies of their captured responses. It also corrects
Darwin process inspection, installs the PDF renderer from the Ubuntu archive
only in continuous integration (CI) and fixes reassessment of compacted
scientific history.

## Result coverage requires the bound search records

- Through 0.58.1, the post gate required the bodies of the captured provider
  responses of every search bound by the openness minimum in the actual
  request of each problem result review. Reduction step 6 of a text route
  withholds those bodies when a packet exceeds its input limit, so verbose
  bound searches could leave `problem_evidence_unassessed`, the finding for
  incomplete result coverage, with no way to clear it on that route.
- On the Sidorenko girth-six record at revision 432, the result packets were
  about 4.37 million characters against a limit of 1.3 million. Version
  0.58.1 listed 20 and 11 withheld captured responses for its two result
  reviews.
- The check in `research_harness/research_decisions._assess_problem_coverage`
  now requires the search records without requiring those response bodies.
  The twelve evidence keys `claim`, `openness`, `openness_searches`, `value`,
  `assessment`, `assessment_evidence`, `attempt`, `results`, `citations`,
  `readings`, `computations` and `formal_checks` must still be present and
  equal their current expected values in a current packet of each review's
  actual request, including null and empty values. The `openness_searches`
  key holds each bound search record with its queries, coverage, the
  disposition of every found work and its captured source records.
- The actual request must still deliver every reading and the exact bytes
  of the artifacts of assessment evidence, computations and formal checks
  to both reviewers. The packet still attaches the captured responses, and
  a route that admits their bodies delivers them. Packets, prompts, the
  transport in `review_transport.py`, recorded requests and the evidence
  digest are unchanged.
- This narrows the rule set by the math-conjecturer design review on
  2026-10-19 in finding A3, which required result reviewers to receive the
  bound searches and the captured evidence and required coverage of both.

The explanation of `problem_evidence_unassessed` is now:

> Obtain both observed results from actual requests that carry the current
> problem evidence, deliver every reading of it and attach the exact bytes of
> the artifacts of its assessment evidence, computations and formal checks.

## A failed Darwin libproc call is an error

- Apple's xnu source in `libsyscall/wrappers/libproc/libproc.c` returns zero
  and sets errno when `proc_listpgrppids` or `proc_pidinfo` fails. The old
  enumeration check, `count < 0`, did not detect that failure. It read the
  failure as an empty process group, and probe cleanup concluded that every
  process in the group had ended.
- Both calls in `research_harness/probe_supervision.py` now clear the
  ctypes errno first. A process-group enumeration that returns zero with
  errno set raises `OSError`, and a short process-identity result is
  classified by the errno of its own call.
- Astra found this defect as finding F2 in the review of 0.58.1.

## CI installs pdftoppm from the Ubuntu archive only

The CI workflow installs `pdftoppm`, the PDF page renderer, from the Ubuntu
archive only. The runner image's Microsoft repository returned 403 to
`apt-get update` in the 0.58.0 push run 39793165650 and the 0.58.1 tag run
39853437464. The shard failed before its tests ran. The installation in
`.github/workflows/ci.yml` now uses a source list for the Ubuntu archive.

## Compacted history no longer crashes the reassessment check

- On a read-only copy of the extremal-graph-stability problem record,
  0.58.0 and 0.58.1 raised `AttributeError: 'str' object has no attribute
  'get'` while reading the state of the result assignment
  `result-astra-sharp-three-v6`. The failure stopped `next`, the post gate
  and every command that read that assignment.
- The objection walk in
  `research_harness/review_supplied_evidence.collect_qualified_objections`
  recurses into a packet's scientific history. Under the history compaction
  mode `HISTORY_COMPACT_V2`, a replayed turn uses a placeholder with
  `delivery: "repeated-in-the-current-packet"` for a part that the current
  packet repeats. The walk now reads an objection list only where a list
  is delivered.
- With 0.59.0, that store copy reads 5 routes and 33 assignments, 30 ready,
  as 0.58.0 at `5011adb` read it before commit `8205041` introduced the
  crash.

## Not in this release

- Citation checks still read the frozen packets. Applying the
  actual-request rule requires the union of the actual requests of a
  review's lineage, because a session replays its earlier turns compacted.
- An assignment that cannot fit is not refused before `review-run`. The
  export already warns about it.
- The runtime identity of `openai_responses_v1` remains the digest of
  `review_transport.py`, which is unchanged.
