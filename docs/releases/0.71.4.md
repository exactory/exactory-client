# Exactory 0.71.4

This patch lets the file guard skip a shell word or tool path only when checking it raises `OSError` with
`errno.ENAMETOOLONG`. An overlong word or path no longer stops an unrelated tool call. Every other unexpected check
failure still produces an explicit denial.

## Why

The file guard splits a writing Bash command into words and checks words containing `/` against the harness-owned
files. Apostrophes in a heredoc body can make `shlex.split` combine several hundred bytes into one word. When that
word contains `/`, a filesystem check can raise `OSError` with `ENAMETOOLONG`. The exception reached the hook's
catch-all denial instead of leaving the call silent. An overlong Write, Edit or NotebookEdit path could fail the
owned-file or generated-output checks the same way.

## What changed

`guard_attack_files.py` catches `OSError` while resolving and checking each shell word, and skips that word only
when its errno is `errno.ENAMETOOLONG`. It continues checking later words, so a later path to a harness-owned file
is still denied. For Write, Edit and NotebookEdit, only `ENAMETOOLONG` during the target checks treats that target
as outside the guarded files and folders. These cases are silent.

At these three exception boundaries, every other `OSError`, including `PermissionError` or an unexpected
`FileNotFoundError`, propagates to the hook's existing catch-all denial, which says that the file guard could not
check the tool call. An unreadable path is not evidence that the target is outside the guarded files or folders.

The controller check `math_search.guard` and its error boundary are unchanged. The existing denials of writes to
harness-owned files and generated output folders remain. There are no record, route, stored contract or pinned
module changes.

## Upgrade

No action is necessary.

## Checks

The overlong heredoc and tool-path regressions, including a later owned shell path and Write, Edit and NotebookEdit
targets, pass on Python 3.12.8 and 3.9.6. Tests with directories whose mode is `000` confirm the catch-all denials
for permission errors in shell-word, workspace and output-view checks, and the unchanged controller denial for a
Write beneath such a directory. These permission tests skip root, which ignores the permission bits.

The full hook test modules and the version, manifest and release-note tests pass on both interpreters, with
`codex/generate.py --check` and `git diff --check`.
