# Exactory 0.66.2

This release lowers the peak memory of history validation and starts push
runs of CI only on `main`. The work is recorded in
`misc/harness-improvement/20261024163824-open-records-v13-v15-v16-v17`
(`TASKS.md`, section T11) of the exactory repository.

## Lower peak memory of history validation (v15)

- `_encode_json` checks the UTF-8 form of an encoded value in pieces of
  65,536 characters, and `_digest` gives the same bytes to SHA-256 piece by
  piece. Before, the codec allocated a buffer of up to four bytes per
  character for the whole value. The returned text, the digests and the
  refusals are unchanged.
- History validation releases each completed event, its receipt and its
  database row before it decodes the next event and the current records.

On a synthetic store of 65.0 MB with large nested records (five runs each,
medians), the peak resident size fell from 1.419 GB on 0.65.1 and on the
JSON-walk change of 0.66.0 to 0.959 GB (-32 %), and the user CPU stayed 33 %
below 0.65.1 (6.779 s to 4.522 s). On a synthetic store of 70.2 MB with
uniform records (three runs each), the peak fell from 0.928 GB (0.65.1) and
0.953 GB (0.66.0) to 0.708 GB.

The 0.66.0 note reported one write on the 4.1 GB store of study
`2409.17337` with a peak of 17.2 GB, against 14.9 GB on 0.65.1. The
investigation found no larger live JSON allocation in that change. The
cause of that difference is not proven. The working assumption is that
macOS keeps freed large blocks resident. This release was not measured on
that store before this note.

## CI

A push starts CI only on `main`. Pull requests start CI as before. Pushes
of tags, `dev`, `local-dev` and other branches no longer start a run, so a
release starts two runs instead of about six. GitHub's workflow syntax
reference states that when only `branches` is defined for `push`, a tag
push starts no run
(https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax).

## Upgrade notes

None. No module that a stored record or a route pins by its bytes changed.

## Tests

- `tests/test_research_json_walk.py`:
  `test_validation_bounds_utf8_buffers_for_large_nested_records`
  authenticates three nested records of one million Unicode characters each
  within a traced bound of 26 MiB, checks the exact bytes and digests around
  piece boundaries, and checks the original refusals for surrogates. It
  failed before the change on Python 3.12 and 3.9.

The current-version pins in `tests/test_codex.py`, `tests/test_manifest.py`
and `tests/test_research_guidance.py` name 0.66.2.
