# Exactory 0.65.0

This release adds five research-harness changes from the open records of
v13 and v17, and makes a small store write of a large study faster and
lighter. The work is recorded in
`misc/harness-improvement/20261024163824-open-records-v13-v15-v16-v17`
of the exactory repository (`TASKS.md`, sections T4, T6 and T8; the v13,
v15 and v17 records).

## Result evidence of any media type (v13 T6)

- A binding admits run outputs of any media type, and an assessment can
  cite a whole output with `{"kind": "artifact"}` or a page of a PDF output
  with a result `pdf` locator.
- Every later reader of result evidence (readiness, result decision,
  manuscript pin and its claim evidence, scientific delivery) checks the
  reference through one function,
  `execution_evidence.validate_result_reference`, against the exact output
  descriptor that the execution recorded.
- One reader of the `pdfinfo` page count, `ocr.read_pdfinfo_page_count`,
  serves OCR and the output PDF reader. It accepts exactly one positive
  `Pages:` field, so a metadata line that injects a second one cannot set
  the count.

## Probe records (v13 T7 and T17)

- Completion-check outputs that the author did not read are stored sealed
  under `research/sources/sealed/`: the bytes are kept, and readers and
  review packets do not receive them.
- `exactory-lab probe` accepts `--cycle-id`, `--program-path` and
  `--read-output` to disclose a program run before its plan. A plan can
  declare `prior_knowledge`, and admission checks that the plan's program
  matches the disclosed runs.

## Publication records (v13 T10 and T11)

- A readiness assessor can record the strict boolean
  `assessor.author_memory_notes_present`.
- New manuscript bundles pin `review_inputs_artifact` and
  `execution_observations_artifact` instead of inline copies, and every
  reader resolves both the new and the old shape. Older records and their
  digests stay as they are.

## Deposit package (v13 T12)

`exactory-draft package --output PATH [--bundle ID_OR_DIGEST] [--include
PATH ...]` writes a ZIP with the frozen code, every input and output of
each run that the manuscript cites, an index and the records. The store is
not changed.

## Reference families (v17 items 1 to 3)

- `import-response --preview` reports, without writing, the existing DOI
  families that an arXiv record's DOI would contradict. A real import
  continues and reports `identity_conflicts`.
- A reference resolution can name `target_family` with evidence; an
  invalid choice is refused with `invalid_family_selection`. Without a
  choice, the ambiguity stays as before. Earlier receipts replay unchanged,
  and earlier reading digests are kept.

## Faster small writes on large stores (v15)

An ordinary artifact registration now authenticates the complete history
twice instead of three times. The artifact preflight and the domain
preparation share one internally owned snapshot with a content fingerprint
computed while the validator visits the history. `Store.mutate` still
validates its own write transaction in full and checks the revision, and
it receives only a proof (database identity, revision and fingerprint).
A new request whose preparation no longer matches the store is refused as
`stale_revision` with the reason `snapshot_identity_mismatch` and no
receipt. No serialized format changes.

Measured on copies of the 4.1 GB store of study `2409.17337` (revision
3558, one plain artifact write each, single samples under other load):
0.63.0 took 578.7 s of user CPU with a peak resident size of 23.0 GB; this
change took 373.5 s (-35 %) and 15.5 GB (-33 %).

## Function names

Every function that these changes added has a name with a verb, for
example `format_utc_now`, `build_program_probe_inventory`,
`find_family_candidates`, `_encode_json_bytes` and the `_Archive` methods
`reserve_parents`, `write_directory`, `write_artifact` and
`write_references`.

## Upgrade notes

Releases before 0.65.0 do not know the new record fields (`program_run`,
`prior_knowledge`, sealed artifact paths, the reference form of manuscript
bundles, `author_memory_notes_present` and `target_family`). Continue work
on a store that uses them with 0.65.0 or later.

## Choices for the owner

These ship as provisional behavior; the owner's merge accepts them.

- Unread outputs (T7) are sealed: the bytes stay. The alternative keeps
  only their hashes.
- Program runs (T17) are disclosed by explicit identifiers, paths and
  hashes. Alternatives are hashes only, or inference from names, times and
  text.
- Memory notes (T10) are an optional boolean. The alternative relies on
  isolated evidence without a field.
- Publication inputs (T11) are stored by reference for new bundles only.
  Alternatives migrate existing records or keep inline copies.
- The deposit package (T12) holds every input of each cited run. The
  alternatives hold only the program and its outputs, or follow the inputs
  to the runs that produced them.
- DOI family conflicts (v17) are reported, and the import continues. The
  alternative refuses the import until the conflict is accepted. An
  explicit, evidenced family choice is allowed; the alternative keeps the
  reference ambiguous.

## Known gaps

The agent-facing texts of these changes (the skills, `docs/research-cli.md`
and `docs/research-workflow.md`) are not written yet, and neither are those
of T13 (draft marker) and T16 (format-only reruns). The commands and fields
above are described only in this note and in the code.

## Not in this release

- The math-solver openness text priority (`lane/0.64.0-openness-priority`):
  it is to be reconsidered on top of the reading chains of 0.64.2.
