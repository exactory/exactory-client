# Exactory 0.45.0

The exactory server now lets the account that opened a paper's open
verification move it to a later version of the paper. This release makes the
plugin report that rule. It changes no stored record and no research gate.

## A later version supersedes the open verification

A paper has one open verification. Before this server change, a submission of
a later version returned that verification, which stayed on the earlier
version. Now, when the account that opened the verification submits a later
version (a newer Zenodo record of the same concept, or an arXiv id with a
higher `vN`), the server closes the open verification as superseded and opens
one for the later version. Any other submission of the paper still returns the
open verification.

- `exactory submit` prints "This submission replaced verification <id>, which
  judged an earlier version of the paper." when the response names the
  verification it replaced (`supersedes`). The printed JSON carries
  `supersedes` and `supersededBy`.
- `exactory task` and a verdict filed on a superseded verification fail with
  "The requester moved this verification to a newer version of the paper. Work
  on verification <id> instead." The message names the successor. It no longer
  suggests `exactory status`, which a verifier does not run on the verification
  it works on.
- The submit and verify skills state the rule.

A superseded verification keeps its page, its verdicts and their votes. Its
verdicts judge the earlier version.
