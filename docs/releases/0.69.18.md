# Exactory 0.69.18

This patch registers the record kind and the command that 0.69.15 added in the two tables that the registry tests
read. The tests `test_research_output_views.RegistryTests.test_every_written_kind_has_a_placement` and
`test_research_check_mode_audit.CommandTableCheckTests.test_check_preserves_every_command_workspace` pass again.

## Why

Version 0.69.15 added the command `problem-citation-metadata`, which writes records of the kind
`problem_citation_metadata`. That release did not add the kind to the placement registry of `output_views`, and it did
not add the command to the table of expected check outcomes of the check-mode audit. Both tests fail on `main` from
0.69.15 to 0.69.17. The release checks of 0.69.15 did not include these two test modules.

## What changed

- `output_views._UNPLACED_KINDS` now lists `problem_citation_metadata`. The views do not show its records, the same
  as the other work-level records (`work_assertion`, `source`, `reading`). An export still carries the citation title
  and authors that the record gives.
- The check-mode audit expects `problem_citation_work_ineligible` for the documented example payload of
  `problem-citation-metadata`, because its `url:` work is not in the audit workspace. This change is in the tests only.

## Upgrade

No action is necessary. Only the tests read `PLACEMENT_BY_KIND`, and no other production code changes. A render reads
the kinds of the view groups, and this release does not change them.

## Checks

Both tests failed on 0.69.17 (`main` at c38911f). With this change, the modules `test_research_output_views` and
`test_research_check_mode_audit` pass on Python 3.12.8 and 3.9.6, and so do the manifest and version tests at
0.69.18. `codex/generate.py --check` and `git diff --check` pass. The full suite runs in CI on the pull request.
