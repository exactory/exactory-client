# Exactory 0.71.7

This patch gives newly rendered reviewer prompts common text version 3. The new text tells the reviewer to write
each top-level field of the turn inside the one JSON object, and to close that object once. Recorded prompts keep
their text and their verification.

## Why

Some reviewer answers were not one JSON object. The reviewer closed the top-level object and then wrote more
top-level fields after the closing brace, or it wrote one extra closing brace at the end. The harness reads the
answer with `json.loads`, so the attempt fails as `review_transport_failure` and the whole reviewer call is lost. The
harness does not repair an answer, and this release keeps that rule.

A read-only measurement on 2026-11-03 found 23 such answers in 7 records. Each answer becomes one valid object when
one brace is removed. In 17 answers the reviewer closed the object early and then wrote more fields:

- `excerpts` (10 answers)
- `source_requests` and `excerpts` (1 answer)
- an invented field and `excerpts` (1 answer)
- `reassessment` (2 answers)
- `objections` and the fields after it (3 answers)

In 6 answers one extra brace followed the complete object. 22 answers came from the Claude CLI route and 1 from a
Codex route. One turn of a problem bar review failed three times in a row this way before its fourth run completed.

On the Claude CLI route, 17 of 366 attempts with common text version 2 failed in this way. The failures are in the
prompts whose example object ends before a field that a later part of the prompt adds. These are the groups for
claude-opus-5-5 on common text version 2:

| Group | Attempts | One-brace failures |
| --- | --- | --- |
| Problem bar with excerpt rules (the example ends before `excerpts`) | 45 | 14 (13 early closes, 1 extra brace) |
| Problem bar without excerpt rules | 8 | 0 |
| Problem bar context repair with excerpt rules (the suffix places its field inside the object) | 15 | 0 |
| Problem result evidence parts, final turn | 26 | 3 extra braces |
| Problem result evidence parts, part turn (the example shows `excerpts` inside the object) | 112 | 0 |
| Openness reading turns (the shape lists `excerpts`) | 132 | 0 |

The history of the context-repair suffix agrees. The first suffix asked for "an additional reassessment object", and
3 of its 4 Claude attempts closed the object early. The later suffixes say that the field goes inside the object
before its closing brace. None of their 32 Claude attempts failed in this way, and 23 of them completed.

## What changed

Common text version 3 is version 2 with six sentences after "Start the object at the first column of its line.":

> Later parts of these instructions can add top-level fields or replace the response shape for this turn. Put each
> top-level field you write for this turn inside the top-level object, before its closing brace. An example's closing
> brace does not end your top-level object while you still have fields to write. Close the top-level object once,
> after its last field. After that brace, write nothing, not even another brace, unless you use the correction form
> below. A top-level object closed before all its intended fields are written is wrong.

`COMMON_VERSION` is now 3. A newly rendered prompt opens with version 3, and its envelope records
`common_version: 3`. Template ids, role texts, examples and phase rules do not change.

The staged prompt builder accepted only common text version 2. It now accepts version 2 and every later registered
version. It renders the base prompt with that version and records the version in the envelope. It still refuses
version 1, which no staged prompt used.

Answer parsing and the transports do not change. An answer with text after its closing brace still fails. The
`RETRACTED` correction form of version 2 is still the only correction form. The Claude CLI route reads it, and the
other routes read exactly one object.

## Upgrade

No action is necessary. Only newly rendered prompts get version 3. Recorded assignments, attempts, prompts,
packets, requests and receipts keep their bytes. Each one verifies under the common text version that it records. The
change of the common text alone causes no refresh and no adjudicator replacement.

A session that continues after the upgrade gets version 3 for its new turns. This applies to a source-request
session, an evidence parts series, an openness reading chain and a context repair. The earlier turns keep version 2
and still verify. A staged task that was planned before the upgrade keeps its planned prompt and request digest
when its child is assigned after the upgrade.

The effect on the failure rate is not measured yet. The evidence above supports a placement sentence next to the
field. It says less about a sentence at the start of the prompt, and least about the extra closing brace.

## Checks

New tests pin the version 2 envelopes that 0.67.0 to 0.71.6 record. The fixture holds 182 cases, rendered from a
clean export of `ee36aa3` (0.71.6 renders the same envelopes). Other new tests pin the three common texts by digest
and the version 3 default of every prompt family. They also make sure that a relabeled or altered envelope is
refused.

Integration tests carry these sessions across the upgrade: a problem bar source session, an evidence parts series,
an openness reading chain, a math openness chain, a context repair and a staged epoch. Further tests compare the
instructions of a request with the prompt of its assignment on all five route adapters. Other tests pin the refusal
of the measured answer patterns, with and without a later `RETRACTED` line.

The changed and related test modules pass on Python 3.12.8 and 3.9.6, and so do the version, manifest and
release-note tests. `codex/generate.py --check` and `git diff --check` pass. The route-pinned modules, `FIT_ORDER`
and `EARLIER_FIT_ORDERS` are unchanged.
