# Exactory 0.43.0

This release makes a manuscript account for the literature that its study used.
It adds no stored record kind. The research constitution stays at version 5, and
no study revalidates.

## Citation accounting at the manuscript pin

A study can read many sources in full and still cite few of them. The pin now
compares the pinned bibliography with two sets of works:

- every work with a recorded full-text reading
- every work that a selected research search of the five purposes cites

The bibliography cites a work when the work's arXiv family, a DOI of the work or
of a provider alias, or a title of at least two words occurs in it. The lineage
gate reads the same evidence.

Each accounted work that the bibliography does not cite needs one item in the
new optional payload field `citation_accounting`:

- `{"work_id": ..., "cited_as": "<key>"}` names the BibTeX entry that cites the
  work, for example a published version that the store does not link to the
  preprint that the study read.
- `{"work_id": ..., "reason": ...}` states why the paper does not cite the work.

If a work is not accounted for, the pin stops with
`citation_accounting_incomplete`. The error lists each work and the reason that
it is accounted: `fulltext` or `search:<purpose>`. A malformed, duplicate or
unneeded item, or an unknown key, is `invalid_citation_accounting`. The bundle
keeps the result as `citation_accounting: {cited, not_cited}`, so the decision
is part of the bundle digest.

## `exactory-check`

- `add --arxiv-id` cites the published version when the arXiv record names its
  DOI, or when exactly one Crossref journal, proceedings or chapter record has the
  same title and first-author family name. The command prints which version the
  entry cites and why. `--preprint` keeps the preprint.
- `add` renders the inline markup of Crossref and DataCite titles as LaTeX:
  `Sb<sub>2</sub>Te<sub>3</sub>` becomes `Sb$_{2}$Te$_{3}$`. An inline MathML
  formula, as in many APS titles, becomes LaTeX with a space on each side.
  Title matching ignores the markup, so older entries with literal tags still
  verify.
- The lookup cache uses only the primary identity of an entry: the DOI, else
  the arXiv identifier, else the title. Before this release, a DOI entry could
  be compared with a cached record of its preprint through the shared title and
  fail with `author_mismatch`.
- `lookup` reads the LaTeX files under the bibliography's directory. An entry
  that no citation command cites is blocking. A sentence that makes a prior-art
  statement without a citation is a warning with its file and line. The report
  has a new `manuscript` object with these findings and the SHA-256 of each
  LaTeX file.
- `gate` treats the report as stale when a LaTeX file changes, when a LaTeX
  file is added or removed, or when the report has no `manuscript` object.

## Skills

The write skill asks for the published version of each cited paper, for the
exact preprint version wherever a value was read from a preprint, and for
`citation_accounting` at the pin. Its stage report now includes a citation map
by the five purposes and the original source of each named law, model, method
and tool. The evaluate skill treats uncited entries as blocking findings.

## Upgrade

1. In each draft workspace, run `exactory-check lookup` again. A report from
   0.42.2 has no `manuscript` object, so `gate` treats it as stale.
2. If `lookup` lists an uncited entry, cite it where it supports a statement, or
   remove it.
3. Before the next `exactory-research manuscript` pin, add `citation_accounting`
   items for the works that the pin lists. Bundles pinned before 0.43.0 do not
   change.
