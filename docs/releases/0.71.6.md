# Exactory 0.71.6

This patch lets a qualified unavailability answer a reviewer's exact source request with captured evidence,
without granting reading credit or waiving scientific obligations.

## Why

A reviewer could request the abstract of an old journal paper whose complete Crossref and OpenAlex records
contained no abstract. The harness could already record that retrieval limitation under an availability policy,
but source continuations ignored it. The request stayed pending, preventing a final assessment indefinitely.

## What changed

`reading.qualify_availability` shares the record-time qualification checks with review delivery. Registry absence
requires parsed responses bound to the work and coverage of every registry addressing its current identifiers.
Imported web/MCP sources retain their binding through the work's source IDs. Every qualifying response is reread
through the artifact store; missing or altered bytes retain the store's refusal codes.

`bar_sources` first tries the existing complete-source delivery. When that fails, a currently qualified
availability record for the exact requested version and depth can answer as `unavailable_qualified`. The answer
includes its policy, actual registry or terminal-origin response bodies, and typed provenance. A partial abstract
of the requested record arrives alongside the qualification and stays partial. At abstract depth, held extracted
full text is advertised as a requestable alternative after verifying its source binding and bytes, without
artifact references or a charge to the full-text reading budget. An invalid optional alternative is omitted;
independently qualified evidence still settles the abstract request. A terminal failure cannot excuse pending
required units of any held full-text capture. Accepted native identifier spellings are normalized for matching
without borrowing material from aliases or other versions.

An evidenced qualified answer settles the retrieval request. Partial and unqualified unavailable answers stay
pending. Existing capacity batching keeps the whole answer and its evidence together; an answer deferred for
capacity stays pending. Qualification is progress even when the work's capture digest is unchanged, while an
unchanged repeated answer still refuses. Qualification grants neither reading nor scientific-support credit and
does not enter complete-source selection. Critical dependencies, reading and bibliography requirements remain.

There are no record migrations, canonical prompt changes, batch-guidance changes or pinned-module changes.
Abstract borrowing across alias records and complete publisher-import support are deferred.

## Upgrade

No migration is necessary. A previously observed final whose frozen packet still has pending requests remains
unrecordable. Continue the same reviewer session to deliver the qualified answers, then obtain a newly observed
final. The reviewer may request full text or retain the source limitation in its assessment.

## Checks

Regression coverage exercises registry binding and current coverage, response integrity, partial abstracts,
reference-free full-text alternatives, complete-source precedence, terminal failures and held required units,
critical reading obligations, atomic capacity deferral, progress, complete-source exclusion and frozen finals.
All 158 tests in the changed modules pass on Python 3.12.8, 3.9.6 and 3.14.6, including the manifest, Codex and
research-guidance tests. The Python 3.12 run including pinned result-history tests passes all 185 tests.
Generated-file consistency, compilation and whitespace checks pass. All 11 pinned module hashes, the canonical
source-request prompt and the source-batch guidance are unchanged.
