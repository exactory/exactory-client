# Exactory 0.62.0

This release adds JATS XML full text, repairs figure resource discovery and
checks manuscript claim evidence before the pin. It reports and restores
changed manuscript files, creates a draft marker when a study enters writing,
admits mechanically checked format-only reruns and reports missing hook
scripts with an exit status for each event. These are the seven lanes merged
in `ef69c28` on top of 0.61.0.

The implementation, design choices and evidence are recorded in
`misc/harness-improvement/20261024163824-open-records-v13-v15-v16-v17`
of the exactory repository, section T4 of `TASKS.md` and `designs/`.

## Figure images on PubMed Central pages (T3)

The resource inventory of a saved HTML page finds a figure by the `figure`
element or by the classes `figure` and `ltx_figure`. It now also treats an
element whose class names, in any letter case, include `fig` as a figure
container. An enclosing figure wrapper takes precedence over a `picture` or
SVG inside it. Before, a caption inside such a wrapper missed its sibling
image, and an anchor inside a nested `picture` could miss the other panels.
Six tests on an authored PMC page pin those boundaries and the image reading.

The live PubMed Central page PMC13104172 and the stored page of study
2601.01283 wrap every figure in a `figure` element of class `fig`, which the
inventory already recognized. The class rule itself changes nothing on those
pages. In the recorded live check, `fulltext` captured the article and
`visual` acquired figure 1's CDN image, 117,117 bytes with
`verified_container`, bound to the saved HTML's source id and hash.

That check also found a false resource ending in `%23c`: the CSS `url()`
pattern stopped inside a quoted SVG data URI and resolved its inner
`url(%23c)` against the page URL. This defect was fixed in `32f0d6d`, included
in this release. A quoted value is now read to its own closing quote, and an
unquoted value to the closing parenthesis. Document styles, inline styles,
presentation attributes and standalone SVG validation use the same reader.
Thirteen tests cover the reader and the SVG guards.

A check of the saved live page with the fix lists only the CDN image and four
`visual_document_style_unsupported` items for document styles and stylesheet
links. The reading stays partial even after the asset is linked and
inspected, because the harness has no CSS cascade evaluator. That existing
stylesheet rule remains an open choice.

In tests, relative image URLs resolve against the saved page's URL, so a
Europe PMC HTML capture with the same markup follows the same route. No live
Europe PMC HTML page was checked. `visual` still accepts only direct images
referenced by the selected HTML unit. JATS XML image acquisition and members
of supplementary archives remain unsupported; an archive hyperlink is refused
before a request. The returned `asset_link` belongs in the unit locator's
`assets` in a new bundle and in the reading's inspection, as the CLI reference
now describes.

No command, field, record kind or obligation kind is added by this lane.
By code inspection, a current check of an older unit inside a non-`figure`
wrapper of class `fig` can now require sibling images that its earlier
inventory missed. Such a reading can become partial until the missing,
pending or unlinked assets are supplied and inspected. Recorded results are
not rewritten; this particular earlier-wrapper case has no dedicated test.

## JATS XML full text (T2)

A `fulltext` request now accepts `application/xml` and `text/xml`, previously
refused as `unexpected_mime`. When the root element is `article`, the
extractor `jats` saves the whole article's text, including front matter, body
and back matter, with a line break at each block element. The capture has
`includes_abstract: true` when the abstract has non-heading text, and the
optional field `visual_asset_names` lists the `graphic` references of each
`fig`. These are names only; no image is fetched.

Body content is text in paragraphs, list items, table cells or similar
elements inside `body`, outside headings, abstracts and metadata. An article
without such text is a `landing_page`; other XML stays
`unsupported_fulltext`. Element names are matched by local name, so namespaced
documents read the same. Extraction also accepts `Text/XML` and
`application/xml; charset=utf-8` without rewriting the reported type passed
to the extractor.

The parser loads no external DTD or entity and expands no declared entity.
An internal entity declaration gives `xml_internal_entity`; a reference to
an external entity or to one defined only in an unread external DTD gives
`xml_external_entity`. Invalid XML gives `malformed_xml`. Predefined entities
and numeric character references read normally. A refused extraction keeps
the original bytes and leaves the capture pending with its reason.

In the recorded live check on 2026-10-25, the Europe PMC `fullTextXML`
endpoint for PMC13104172 returned the same 120,467 bytes that study
2601.01283 had stored when the harness refused XML. The capture is extracted
with `jats`, includes its abstract, retains the five figure names
`nn5c21838_0001.jpg` to `nn5c21838_0005.jpg` and saves 45,152 bytes of text.
A span locator over a body passage validates.

Earlier captures and operation results stay as recorded. Replaying an older
request that returned `unexpected_mime` returns that result without an HTTP
request; a new request id captures the URL again. No command, obligation or
record kind is added. The new figure-name field appears only on an extracted
JATS capture. The CLI reference and the full-text module docstring describe
the route. Nineteen tests cover extraction, entities, acquisition, earlier
results and media-type spellings.

## Claim evidence before the pin (T8)

The new read-only command `exactory-research check-claims --file FILE` reads
the `claim_evidence` array of a `manuscript` payload, or the whole payload,
and compares each reference with the evidence of the current assessed
candidate. It needs the candidate but not the readiness review, so an author
runs it while building the mapping and before that review.

When every reference is candidate evidence, it exits 0 and prints
`{revision, mismatches: []}`. Otherwise it exits 1 with
`publication_evidence_mismatch`. The message names the first claim id and
reference outside the candidate, and `mismatches` in the details lists every
`{claim_id, evidence}` pair in mapping order. The store is never changed.

The `manuscript` pin uses the same comparison, so its refusal now names the
first claim id and reference and carries the full list. Before, it said only
that every claim must link current candidate evidence, leaving the author to
rebuild that evidence set by hand. The pin now checks claim ids throughout
the mapping before comparing evidence. The write skill, the draft and study
workspace notes, the CLI reference and the workflow say when to run the check
and what to do with its output. Four tests cover the listing, acceptance
before the review, the manuscript input file and the pin's message.

## Restore of a pinned bundle's files (T9)

`manuscript-review` and `manuscript-prediction` refuse a bundle whose working
files differ from the pinned bytes. Until now nothing showed the difference
or put those bytes back. Record v13's sixth finding describes a review refused
after the author recompiled the PDF for the next revision.

`status` now carries `bundle_drift` for the selected bundle while its
measurement is incomplete: the bundle id and digest and each differing file
with its code, `publication_artifact_changed`, `artifact_missing` or
`unsafe_path`. `status --summary` retains the list within its 16 KiB bound,
with long bundle and file names shortened and marked.

The new command `exactory-research restore --bundle DIGEST` writes the pinned
files of any recorded bundle back to their paths. The digest is 64 lowercase
hexadecimal digits. It verifies every pinned object and destination before
writing a file, refuses conflicting pinned bytes at one path, and refuses
destinations under `.exactory`, `.git` or `research/sources/objects` in any
letter case. Equal files are listed as unchanged; missing files and parents
are recreated, with no backup for an absent file.

The provisional behavior stores every differing working file's current bytes
as an `application/octet-stream` backup artifact before the first replacement.
It then writes the pinned bytes and reports each restored path, its pinned
artifact and its backup. No record references the backup, so retain the
returned descriptor to recover the displaced edit. A file that changes during
the restore stops it. No research record is added and the revision does not
change. Eighteen tests cover the command, drift report, earlier records and
a review accepted after a restore. The skills, workspace notes, CLI reference
and workflow describe the command and backup recovery.

## The draft marker on entering writing (T13)

A research objective now accepts optional `title` and `category`. When a
study moves to stage `write` with both fields, no draft record and no marker,
the same mutation records its draft workspace from that exact metadata.
Export writes `.exactory/draft.json` and creates `draft/`. A same-stage study
update can also create the missing draft record; earlier objectives need not
carry the new fields.

At stage `write`, `status` prioritizes `draft_marker_missing` when the marker
is absent or differs from its record, when a marker exists without a draft
record, or when the metadata is missing. The message names the missing fields
or the step needed to export, create or explicitly adopt the marker. An
existing unrecorded marker is preserved.

The authorship hook is unchanged. A whole-source Write after marker creation
uses its existing authorship record; sources written before the marker
receive no backfilled authorship credit. An earlier implementation that read
and changed the study store on every Write was removed: the hook has a
15-second timeout, while measured reads of real study stores take far longer.
Twelve tests cover the marker, status, replay, host hook and deposit
preflight.

## Hooks across plugin updates (T15)

Every generated hook command now checks that its Python entrypoint exists
before invoking it. If the script is missing, it writes this sentence to
stderr and leaves stdout empty:

```text
[exactory] The Exactory plugin was updated during this session; start a new session.
```

On both hosts, a missing PreToolUse script exits 2, keeping the guard closed;
a missing Stop script exits 0, allowing the session to stop. Missing
PostToolUse and SessionStart scripts exit 1. The intended nonblocking handling
of code 1 for those two events remains unverified in Codex. A script that
exists runs with `exec` and keeps its own arguments, streams and exit status.

The change diagnoses missing files and avoids the repeated Stop refusal;
it does not retain a loaded version or switch the session to the new version.
A session that loaded 0.61.0 or earlier still fails the old way when an update
removes its files: Python exits 2 before a hook can run. Only sessions that
loaded the new commands can show the sentence after a later update.

The Codex guide and README tell an affected user to start a new session, then
open `/hooks` and review and trust the changed hooks. Codex skips a changed
hook until it is trusted. `codex/generate.py` now generates `hooks/hooks.json`
for Claude Code as well as `codex/hooks.json` and the Codex skill entrypoints.
Eleven tests exercise all 21 registered commands and generation checks. Same
session continuity across an update remains open.

## Mechanically checked format-only reruns (T16)

An execution admission may now name `format_only_of`, the id of a completed,
assessed, managed execution of the same immutable plan. This permits a format
change after an assessed scientific failure without treating it as an attempt
to resolve that failure. The admission retains the plan's recorded strategy
failures, skips the reopening check and closed-cycle refusal, and charges the
original strategy budget. All other freshness checks, the pending reservation
rule and budget limits still apply, including the reviewed tranche.

Recording accepts the execution only when every output equals an earlier
output of the same requirement, byte for byte or as an equal strict JSON
value, and every earlier output is covered. JSON booleans never equal
numbers. A successful execution carries
`format_only_of: {execution_id, execution_digest}`. A mismatch is refused as
`format_only_output_mismatch` without recording an execution or outcome; its
admission reservation stays pending.

The conversion preserves earlier executions, assessments and failures. Its
outputs cannot count as changed evidence to reopen a failure, and records
without the field retain their earlier shape and behavior. The record's own
case, a PNG figure redrawn as SVG, is not covered by mechanical equality.
Sixteen new tests in `tests/test_research_development.py` cover the exception
and its limits.

## Choices for the owner

T2, T3, T9, T13, T15 and T16 ship their provisional behavior in this release.
Their design notes record these alternatives:

- T2, JATS: alternatives to matching local names in any namespace are
  unnamespaced JATS only or an explicit namespace allowlist. Alternatives to
  ignoring external DTDs and refusing internal entity declarations are to
  refuse every DOCTYPE or permit bounded internal expansion with an explicit
  output-size limit and further security tests.
- T3, figure resources: the alternative to direct HTML images is hash-bound
  archive members, with retained archive and member provenance, bounded
  extraction and path checks. This needs new acquisition, locator and reading
  support; whether document stylesheets keep blocking figure readings is a
  separate unresolved choice.
- T9, restore: alternatives to preserving backups are to refuse a differing
  file or overwrite it without a backup. Backups retain later edits but add
  storage for each distinct displaced byte sequence.
- T13, draft creation: alternatives to explicit objective metadata with a
  missing-marker obligation are to block writing until metadata exists,
  always require explicit draft initialization, or infer missing values.
  Alternatives to no pre-marker credit are a new mechanism to observe future
  Writes within the hook's 15-second limit without study-store access, or a
  weaker evidence policy accepting narratives or file existence.
- T15, updates: alternatives to the missing-script diagnostic are host
  retention with session leases, a stable entrypoint dispatching to the
  current version, or a protected snapshot of the complete runtime per
  session. These require host lifecycle support, and dispatch also requires
  approval of the selected code and an atomic target switch.
- T16, format reruns: alternatives to byte or JSON equality are versioned
  validators for specific conversions, or independent conversion reviews
  retaining exact source and output references and reviewer provenance.
  A PNG-to-SVG validator also needs the binary-evidence route and must check
  that the wrapper preserves the visible image, not only its embedded bytes.
