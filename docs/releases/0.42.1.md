# Exactory 0.42.1

This release corrects 0.42.0 after an independent review of its implementation.
The direction of 0.42.0 stays: a research study records the challenges ahead of
it, every blind review names what each score below 4 needs to reach 4, and a
contribution analysis follows each measurement. One contract of 0.42.0 changes,
because it could not do what it was made for.

## The investigation is kept as captured responses

In 0.42.0 the contribution analysis named searches with a new purpose,
`grand_challenge`, that the preparation left out so that the measured bundle
stayed current. That did not hold. A search needs its captured response imported
first, and the import changes the record of every held work the response
returns: a root, a cohort member, or a newer version of either. A forward-looking
query in the study's own field returns such works, and the measured bundle was
then no longer current, so the round decision on it was refused.

In 0.42.1 the analysis carries its investigation itself:

```json
"investigation": [{"query": "finite bound multivariate inputs open problem",
                   "response": {"sha256": "...", "path": "...", "size": 1234, "media_type": "application/json"},
                   "finding": "Two groups state the multivariate case as open; no paper establishes it."}]
```

Save each original response in the workspace and pin it with `artifact`. Nothing
is imported, so the bundle stays current whatever the response returns. A query
with its response serves one analysis (`contribution_investigation_reused`). The
harness compares the query and the response bytes and no more; the round packet
delivers the captured responses to the round assessor, who judges them.

`investigation` replaces `searches` in the `contribution-analysis` payload. The
search purpose `grand_challenge`, the bundle's `search_ids` and the code
`contribution_search_missing` are removed. 0.42.0 was current for one day. A
payload written for it needs the new field, and a `grand_challenge` search
recorded under it now counts as an ordinary search record.

As evidence for a step, cite sources the study has already read in full, results,
reviews of the bundle, or a source the study does not hold yet, read in full now.
A work the study holds without a full reading waits for the next round's
literature stage, because reading it changes the preparation.

## Corrections

- A bundle takes three predicting assessors. In 0.42.0 one more prediction made a
  complete measurement incomplete again: the next bundle could then be pinned
  without the owed analysis, and a measured and analyzed bundle could never be
  decided. A fourth predicting assessor is refused
  (`manuscript_prediction_excess`).
- The workflow, the CLI reference and the CLI stage test record `grand-challenge`
  before `target`, because the objective is written against the record. `next`
  names `grand_challenge_missing` after the searches and before the synthesis
  sections: the record needs a source read in full, so it must not hide the
  roots, the readings or the searches. `objective_missing` keeps the early place
  it has had since 0.38.
- A Grand Challenge record needs a research configuration
  (`configuration_missing`, `profile_inapplicable`), and a source that two
  challenges cite is stored once.
- A malformed evidence list or review item of a contribution analysis fails with
  `invalid_contribution_analysis`. In 0.42.0 it failed with `invalid_round`.
- The analysis and the round decision each keep the id and digest of the Grand
  Challenge record that was current when they were recorded. When another record
  has replaced the one the analysis names, the round packet also delivers that
  earlier record as `analysis_grand_challenge`.
- `round.analysis` follows the selected bundle, current or not, and `gate round`
  reports an owed analysis while the selected bundle is not current.
- `status --summary` reports the record id, the number of `ultimate` and
  `near_term` challenges, the first six criterion ids and a count of the rest,
  each id cut at 32 characters. With a large record the 0.42.0 summary reached
  811,173 bytes against its 16 KiB bound.
- A list or an object in a field of an artifact reference fails with a typed
  error. It raised `TypeError` before, in every operation that takes a Link.
- The four examples `grand-challenge`, `contribution-analysis`, `round` and
  `round-review` can now be recorded together; a test keeps them consistent.

## Documents

The CLI reference and the workflow describe the measurement, the analysis and
the decision in the order they run, name every new code, and no longer say that
the review core has eight fields or that no gate reads the measurement. The
skill texts that 0.42.0 changed are corrected the same way, and each list of what a
blind reviewer never sees now names the Grand Challenge record, a contribution
analysis and another reviewer's `changes_for_maximum`.

Dispose of a step you do not pursue as `deferred` unless the evidence rejects
it. A `rejected` candidate can never become a goal, and the analysis fixes a
step's statement for its bundle.

## Native mathematics

`export --kind native` requires complete research preparation, so since 0.42.0 a
mathematical objective with a research-profile foundation also needs a Grand
Challenge record. The native preparation contract in the CLI reference now says
so. The math-solver skill's own list of the preparation does not name the record
yet.

## Upgrade

The research constitution is unchanged at version 5, so a study that adopted it
under 0.42.0 keeps its adoption. A study that opens under 0.42.1 for the first
time since 0.41.0 follows the section "What an existing study owes" of the
[0.42.0 notes](0.42.0.md). A study that recorded a `grand_challenge` search
under 0.42.0 after a pin finds that bundle no longer current
(`publication_readiness_stale`), because the search now counts in the
preparation; it pins again.
