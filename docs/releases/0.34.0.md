# Exactory 0.34.0

This early release adds a persistent mathematical search controller shared by
Claude Code and Codex. It preserves the complete original objective while tracking
reviewed branches, inherited budgets, proof dependencies, controlled execution,
and final delivery. Both plugin manifests identify source version `0.34.0`.
Source version, remote availability, installed version, and active trusted hooks
are separate observations. This document does not establish any installation or
publication, and an ordinary source push creates no GitHub tag or Release.

## Included scope

The release includes implementation Tasks 1 through 6 and 9, with Task 7's skill,
command documentation, generated entrypoints, and executable example aligned to
that scope. Task 8 supplies release integration and regression validation.

- The original claim remains immutable. Reviewed admission creates stable
  obligations and AND/OR proof routes. A continuation retains its inherited
  account and consumed allowance. Imported historical work is explicitly mapped
  with known or unknown usage; import alone supplies no proof acceptance.
- Accepted evidence binds exact statements, assumptions, scope, reviews, source
  versions and dependencies. Partial coverage and root readiness remain distinct
  from an audited final proof with all required deliverables.
- Native journal entries and bounded command, certificate and Lean workloads use
  durable reservations, frozen inputs, exact result identities and reconciliation.
  The Lean inspection checks both the original declaration and its generated
  type-correspondence theorem. External dependency and executable identity hashes
  stream in chunks of at most 1 MiB.
- Finite computation requires a typed, reviewed domain and basis, preflight,
  verification plan and outcome mapping. A finite residue computation requires
  its accepted reduction. Each new finite result must be interpreted before
  another mathematical launch. `UNKNOWN` and a log audit are not proof.
- Historical v1 admissions and completed runs remain readable with their original
  charges and reservation/result identities. A new finite workload on a v1 node
  requires an independently reviewed computation amendment. The amendment does
  not rewrite old history or rearm its budget.
- Host adapters enforce observable command and patch boundaries, route explicit
  focus and custom roots, and preserve pause and Stop decisions. Commands hidden
  inside unobservable wrappers are outside installed enforcement claims.

Native child creation now uses reviewed `search propose`, `search review`, and
`search admit` with `native_parent`. Legacy `init CHILD --from PARENT` refuses with
admission guidance. Native parent records, opening move counts, and depth-one
semantics remain in force. A local native finish does not close the root. The
explicit `local_finish_pending_unused_children` delivery label permits only the
exact unused children that are the sole remaining local finish refusal.

Ordinary status reports recorded completion with evidence freshness `unchecked`.
A full audit is needed to establish current evidence freshness. A recorded active
execution does not establish that a process is alive; inspect its separate process
observation and pending reconciliation state. If a native invocation changed files
without a durable receipt, reconciliation identifies the original command,
arguments and conflicting paths and requires operator handoff. There is no
supported ambiguous-command replay, automatic overwrite, or inference of success
from matching output bytes. See [the recovery contract](../../skills/math-solver/SEARCH.md).

## Still pending

Tasks 10 through 12 remain assigned to the follow-up release, with Task 13's final
integration after them. They include cancellation and total local snapshot-byte

## Upgrade an existing installation

Run upgrades only after the release source is available. Preserve the current
installation scope and all research state. For Claude Code:

```sh
claude plugin marketplace update exactory-ai
claude plugin update exactory@exactory-ai
claude plugin list --json
```

Restart Claude Code to apply the update. Keep the existing `user`, `project`,
`local`, or `managed` scope. Review a changed marketplace installation command
through the host's supported flow.

For Codex, the inspected CLI supports marketplace refresh and installation:

```sh
codex plugin marketplace upgrade exactory-ai
codex plugin add exactory@exactory-ai --json
codex plugin list --marketplace exactory-ai --json
```

Check the returned version and installation path, and read the manifest at that
installed path. They must identify `0.34.0` before reporting an upgrade. Start a
new session to use newly installed content, then review and trust changed hooks
through the supported host flow. A source merge or marketplace refresh alone
does not establish installed or active hook state. If the returned version stays
old, report that version and the observed marketplace source. Do not edit the
plugin cache or delete research state to force an update.

## Waiting agents and existing attacks

Keep the existing pause, pending owned runs, native journal acknowledgements,
evidence identities, and consumed allowances. An update is not authorization to
resume research or adopt an attack. Read the released
[math-solver skill](../../skills/math-solver/SKILL.md) and
[SEARCH.md](../../skills/math-solver/SEARCH.md) before explicitly authorized
adoption. Adopt the original objective and exact historical evidence with the
original budgets and known or unknown consumption preserved. A computation
amendment is separate from both adoption and resume. Do not rename an attack,
create a replacement account, or reset history to obtain a fresh allowance.

## Validation boundary

The release integration exercises a complete tiny residue proof through public
controller and guarded native operations: partial imported coverage, failed
method, inherited continuation, actual frozen certificate execution, result
interpretation, pending unused native child, pause/restart, audited closure and
subsequent invalidation. A frozen pre-amendment terminal v1 history regression
checks compatibility and a new amended run without resetting its old charge.
All reviewer identities in these tests are synthetic software fixtures, not
independent mathematical reviews.

The test gates include client and harness suites, both host payload adapters,
real bounded subprocesses, installed Lean when available, generated parity,
syntax/JSON validation, and the existing Codex branch/subprocess coverage gate
at 80 percent. Fixture payload and subprocess tests are not installed-host smoke.
No live-host plugin smoke, installation, trust change, automatic migration, or
resumption of stopped research is claimed by this source release.
