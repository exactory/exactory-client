# Exactory 0.80.0

This release lets the math-solver controller record the user's instruction that sets one result aside, ends an
objective or resumes a paused one, and lets the run go on under it. It follows 0.79.0. It is phase D of the work
recorded in `misc/harness-improvement/20261106085323-override-of-harness-stops` of the exactory repository. GPT 6
Astra at effort `xhigh` reviewed the design, and the owner authorized the implementation on 2026-11-06.

## Why

- In the controller, a produced result makes acceptance the mandatory next task: `search next` returns
  `prepare_result` with step `acceptance` for the checkpoint until a result is accepted. When the result review
  did not finish, for example when `review-series` stopped with `review_input_too_large`, nothing moved the run
  past that step. `search retreat` needs a declared predicate that has fired, and `search side-interval` passes no
  gate. Two math-conjecturer records stopped this way on 2026-11-03 and 2026-11-04, one after 22 turns and one on
  a 5.9 MB packet, and the owner's written order got them through.
- Nothing ended an objective short of a closure. `search pause` parked one, but `search resume` accepted only a
  host or operator provenance, and no hook on either host captures a user message, so an agent had no recorded way
  to resume on the user's instruction. Real records show what agents did instead: `erdos-124` holds a `resume`
  with `source: "host"` and an agent's actor id, and `extremal-graph-stability` holds a `side_interval` with
  `source: "host"`.
- The owner accepted this principle on 2026-11-06: with the user's instruction, any gate of a pipeline can be
  passed, and the fact is recorded. Without an instruction, nothing passes. The agent's own judgment is never the
  trigger, and a refusal that names a command is not an instruction. 0.79.0 applied it to the stage moves of a
  study, to problem posts and to verdicts. This release applies it to the controller.

## What changed

- `exactory-math search set-aside CHECKPOINT --spec FILE` records the user's instruction that takes one unaccepted
  result out of the acceptance step. The checkpoint stays unaccepted with its verification status, its obligation
  status does not change, and nothing gains proof credit. A set-aside does not clear a pause; when the user's words
  also cover going on, a separate `search resume` with its own derived label follows, and then `search next`
  decides: other pending work can take priority, and the required reassessment can select execution or replanning.
  A second unaccepted checkpoint of the same move stays mandatory. A later normal `search accept` of the set-aside
  checkpoint works and ends the disposition's effect, recorded as `ended_by_acceptance_id`. After an invalidation
  of that acceptance the result is mandatory again, and setting it aside again needs a fresh instruction.
- `exactory-math search end-objective --spec FILE` records the user's instruction that ends the objective without
  a closure. `execution_status` becomes `ended`, and `search next` returns `{kind: "ended", instruction: <the
  user's words>}`. The proof status, the obligations and the closure field do not change. `begin`, `run`,
  `resume`, `pause`, `replan`, `side-interval` and `complete`, `propose`, `review`, `admit` and `adopt` (a retry
  of a recorded request of these four included), and the legacy `plan`, `rank`, `verify` and `fail`, refuse with
  `control_objective_ended`. `accept`, `reassess`, `amend-computation`, `amend-foundation`, `reconcile`, `audit`,
  `render`, `status` and `deliver-attempt` work: they start no work, and an `accept` can need a current
  reassessment. `deliver-closure` refuses with `native_completion_required`. An end records while a native
  intent is pending; `deliver-attempt` then refuses with `native_state_pending` until `search reconcile` clears
  the intent. An ended objective is terminal: `resume` refuses, a fresh `end-objective` refuses too, and another
  objective for the same statement starts only when the user's instruction authorizes that further work.
- An ended objective needs no focus. `search next` returns `ended` for any session, and `status`, `next` and
  `strategy-context` return no handoff for an unfocused session. The SessionStart hook prints nothing, and the
  Stop hook permits the stop without spending a continuation, in a focused session and in any other, on both
  hosts; `hook-stop` on an ended objective needs neither a matching focus nor the reconciliation of a pending
  native intent.
- Both commands take `--expected-revision`, `--request-id` and `--check`. The spec has exactly `objective_id`,
  `message_id`, `session_id`, `instruction` and `provenance`. The instruction is the user's own words, verbatim,
  at most 64 KiB of UTF-8 bytes. `message_id` labels the user's message. One message can back several actions,
  each with its own derived label such as `<label>:resume`, and a derived label does not widen what the words
  cover. A disposition shares the digest check of `objective_id`, `message_id` and `session_id` with `resume`,
  refuses a `message_id` that `side-interval` used, and blocks its own `message_id` for a later side allocation;
  resume and side allocation keep their separate checks. A disposition's identity check refuses with
  `control_instruction_consumed`. These checks do not establish that an instruction is new, and the controller
  cannot tell a new label on an old message from a new message.
- Provenance. No hook on either host captures a user message, so no host authenticates an instruction. The two
  new commands accept exactly `{"source": "reported_by_agent"}`, with no other field, and that is what an agent
  writes. It means that the agent reports the user's words. It establishes no authentication and does not show
  who the user was. The host or operator form `{source, actor_id, attestation_id}` stays accepted for a host or
  operator that did authenticate. The controller checks the form and cannot check authorship, so the texts say
  that the rule rests on the agent's honesty and that the record shows the fact to whoever reads it.
- `search resume` and `search side-interval` accept the same two provenance forms, through one shared check. A
  paused objective, whether the harness paused it after three rounds without progress or at the 40th continuation
  of the Stop hook, or `search pause` did, comes back through `search resume` on the user's instruction, with the
  same five spec fields and the reported form. A provenance in neither form is refused with
  `control_provenance_required`; before, it was `invalid_record`. Their other rules do not change: the instruction
  of a resume or a side interval has no size bound, and the consumed identities are the same lists. The `resume`
  and `side_interval` events that real records hold with `source: "host"` stay as they are. `search focus` is
  unchanged and keeps the host or operator form.
- `search status --json` and `final/math/attack/objective.json` list each disposition with the user's words and
  its provenance. The attempt summary of `search deliver-attempt` adds `dispositions` only when one exists, so a
  summary without one keeps its bytes and its digest, and the problem review of a math-conjecturer record
  receives the dispositions in its attempt evidence. Beside them, and only then, the evidence carries
  `dispositions_note`, a fixed text that distinguishes reported instructions and claims of authentication from
  verified facts, and says that a disposition confers no proof credit and does not determine the current
  mathematical status. The reviewer prompts do not change, and evidence without a disposition keeps its bytes and
  its problem evidence digest (`tests/fixtures/math-attempt-without-dispositions.json`). The default record list
  of the archive that `exactory-draft package` builds (`RECORD_KINDS` in `research_harness/deposit_package.py`)
  omits `native_attempt`, and the deposit disclosure of 0.79.0 names `gate_override` records only and quotes no
  disposition. A file that is explicitly included in the archive can still carry the words into a published
  archive, and exported reviewer output (`reviews.json` of a staged review in a problem export) can quote them.
- The refusal messages of the two commands, of the shared provenance check and of `control_objective_ended`
  state what is needed on the condition that the user gave the instruction, and otherwise say to report the stop.
  No message asks the agent to supply an instruction. The denial of the unit-flow hook, for a unit written before
  `stall`, now says to follow `search next` in a managed objective, to deliver any due attempt and stop when it
  returns `ended`, and to continue at stage 5 in an attack without a controller; the hook reads no controller
  state.
- `SEARCH.md` has the subsection "Dispositions on the user's instruction", lists `ended` among the actions of
  `search next`, the stop rules and the derived control fields, and states the two provenance forms of `resume`
  and `side-interval`. The `math-solver` skill links to the subsection where a result review can stop the run, in
  stage 0 for an objective whose `search next` returns `ended`, and for the resume of a paused objective. The
  `math-conjecturer` skill says that an ended objective is delivered like any other and that its summary carries
  the dispositions. The shared section "Stops and overrides" of `docs/research-workflow.md` has the math-solver
  part, with `search pause` as the park and `search resume` as the way back, and no longer defers the controller
  to a later release.
- The regression ledger has two new `real_shape` entries, `override-math-result-set-aside` with twelve tests and
  `override-math-objective-end` with sixteen. `skills/math-solver/harness/tests/test_search_dispositions.py` has 31
  tests, and `tests/test_math_attempt_dispositions.py` two.
- Not in this release: the classes of stops and the automatic pass of a stop that the harness classifies as its
  own defect (phase C).

Records written by earlier releases do not change; `control.dispositions` exists only after one of the two
commands records it, and a plugin older than 0.80.0 refuses a record that holds one. No migration is necessary.

## Checks

- 22 test modules that touch the change pass on Python 3.12.8 and 3.9.6, with 412 tests each, on the final text. They
  include the hook, ledger, guidance, release-record, problem-attempt and review-consumer modules.
- The whole math-solver harness suite passes on Python 3.9.6, with 1,085 tests, on the final text. On Python 3.12.8
  it ran with 1,084 passes and one failure in `tests.test_search_runtime`, a test that compares the digest of the
  controller's sources. Those sources were being edited during that run; the link is an inference from the times. That
  module passes alone, with 8 tests, on the final text.
- `codex/generate.py --check` and `git diff --check` pass. No protected module changes: none of the files listed in
  `tests/fixtures/failed_request_history/protected-baseline.json` is in this release.
- The supervisor ran the real commands on fixture records from the test support before this note: after a
  set-aside, `next` moved to `reassess_strategies`, then `replan`; an end with a pending move recorded, and
  `deliver-attempt` worked; an `accept` after the end worked, and the state stayed `ended`; the file guard passed
  the record's own writes and commands when the objective was ended.
- That review found four defects before release, and each is fixed in this release with a test:
  `end-objective` was refused while a native intent was pending although `pause` was accepted; a 6 MB
  instruction was recorded with no bound, and the bound is now 64 KiB; `tests/test_research_check_mode_audit.py`
  failed for both commands; a function-level import was repeated in nine places.
- The first text pass reported that a paused objective had no honest way back, and that nothing a reviewer reads
  defines a disposition. So `resume` and `side-interval` now take the reported form, and the reviewer evidence
  carries `dispositions_note`.
- One review by Astra 6 at `xhigh` of the code, whose sandbox refused temporary directories, so 25 filesystem tests did
  not reach their assertions there: it observed no gain of proof credit, and 35 fixture prefixes kept their bytes. It
  found that `propose` recorded after an end, that the SessionStart hook asked for work in an unfocused session, that
  the unit-flow denial told an ended objective to go on, and that one test never ran the replan it names. All four
  are fixed. It also found two items that exist at 0.79.0 and stay as they are: a `search` command whose spec file lies inside a node adds an entry to that node's activity log, and
  `search reconcile` then refuses a pending native intent, so the texts say to write the spec outside the node; and
  `search resume` and `search side-interval` can share one message identity, because refusing it could refuse
  events that earlier releases accepted.
- The texts were written by Fable 5.1 and reviewed once by Astra 6 at `max`. Its findings are applied, except the
  marking of historical design documents under `docs/superpowers/` and the removal of this note's opening history,
  which is the form of the earlier notes.
