# Exactory 0.35.0

Both plugin manifests identify version `0.35.0`.

## Mandatory strategy reassessment

The math-solver controller now requires a reviewed reassessment before new
research after progress, a failed attempt, or a change to the available methods,
remaining obligations, or planning priorities. This applies within a search pass
and to repeated producers inside an existing move reservation.

- `search strategy-context` returns the evidence, current methods, retained
  failures, planning priorities, and digests needed for an assessment.
- `search reassess` records an independently reviewed decision to continue,
  revise, defer, or retire every current method. It also records hypotheses,
  success and failure criteria, and the order of continuing methods.
- Assessments are bound to the current evidence and native planning files.
  A changed problem, plan, or context prevents execution until the assessment
  is current. The controller checks this again before releasing a producer.
- Failed-method history remains available after replanning. Retrying a related
  failed method requires changed inputs and newer evidence; a failed node cannot
  be restored by reassessment.

Recovery, pending-run interpretation, result verification, required cash-out,
and root completion keep their existing priority. Reassessment grants no proof
credit or extra budget. See the
[assessment schema and workflow](../../skills/math-solver/SEARCH.md#mandatory-strategy-reassessment).

## Scheduling and account fixes

- A reviewed replan can order direct obligations and explicitly defer eligible
  investigations that have not started. Deferred nodes remain visible in the
  search tree and lineage records, and can be restored through a later replan.
  These choices form part of the context used for strategy reassessment.
- Execution on a renewed account audits the node's current account while
  retaining the original admission evidence. It no longer incorrectly resolves
  the superseded account as the execution account.

This release also includes the problem-transition and reviewed native-recovery
fixes documented in [0.34.2](0.34.2.md).

## Compatibility and upgrade

Existing controller histories remain readable. Read-only inspection previews
any required strategy-policy upgrade without changing the history. The first
successful `begin` or `reassess` on an older controller records the upgrade in
the same transaction; a rejected request does not write a partial upgrade.

Earlier versions cannot replay the new strategy-policy and reassessment events.
Upgrade all writers of a research root before starting more work with this
version. Preserve the research directory and its complete history when updating.

For Claude Code:

```sh
claude plugin marketplace update exactory-ai
claude plugin update exactory@exactory-ai
claude plugin list --json
```

For Codex:

```sh
codex plugin marketplace upgrade exactory-ai
codex plugin add exactory@exactory-ai --json
codex plugin list --marketplace exactory-ai --json
```

Preserve the existing installation scope. Confirm that the returned version
and installed manifest identify `0.35.0`, then start a new session and review
and trust changed hooks through the host's supported flow. Updating does not
resume paused research, adopt attacks, or reset budgets. The existing-attack
and verification boundaries in the [0.34.0 notes](0.34.0.md) still apply.

## Publication

The release tag is `exactory--v0.35.0`. The marketplace catalogs use the client
repository's default branch without a pinned tag. Publishing this release and
updating an existing installation are separate operations.
