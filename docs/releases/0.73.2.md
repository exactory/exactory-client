# Exactory 0.73.2

This release raises the default time budget of `record-check` from 900 to 3600 seconds, so that a record whose readers
work but take longer than 15 minutes passes the report step. The release follows 0.73.1. The work is recorded in
`misc/harness-improvement/20261104074403-harness-problems-closed-for-good` of the exactory repository.

## Why

On a copy of a live deposited study, `status`, `next` and `obligations` took 1,392, 1,333 and 1,311 s under 0.72.4 and
1,344, 1,331 and 1,303 s under 0.73.0, on the same copy and a loaded machine. The readers work, and 0.73.0 is not slower
than 0.72.4. Inside `record-check`, each reader stopped at the ceiling of 900 s, and the report step failed with
`record_command_timeout`.

The ceiling exists to catch a runaway cost. A slower release is caught by the release procedure, which compares the
readers' times with the previous release on the same copies. A ceiling below the time of a working reader therefore
fails a valid record.

## What changed

- The default of `record-check --time-budget` is 3600 seconds. The value is defined once, in
  `record_check.DEFAULT_TIME_BUDGET_SECONDS`, and the parser takes it from there.
- A smaller or larger budget is still accepted, and a budget that is not a finite positive number is still refused with
  `invalid_input`.
- `docs/research-cli.md` names the new default, and it tells the agent to run `record-check` again with a larger
  `--time-budget` when a reader of the report step fails with `record_command_timeout`.
- `tests/incidents/ledger.json` has the entry `integration-record-check-default-budget` with tests of its real shape.

No route-pinned module changed. No stored record changes, and no migration is necessary.
