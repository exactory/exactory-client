# Exactory 0.73.4

This release makes CI of 0.73.3 pass. The harness code does not change. The release follows 0.73.3. The work is
recorded in `misc/harness-improvement/20261104074403-harness-problems-closed-for-good` of the exactory repository.

## Why

CI of 0.73.3 (run 42028829198) failed one test on shard 0: `test_review_request_parity.test_result_history_06918`,
for the `gate` and `status` reports. The test replays a review history of 0.69.18 and compares the reports with a
frozen copy that a test function adjusts for later presentation changes. In that history, one result slot holds a
pending parts v1 series, and the other slot has no head.

0.73.3 reports a pending head of every kind of series. For this history, the post gate now also lists
`review_task_pending` with `occupied` 1, next to `problem_review_pair_required`. The report adds `slot_outcomes`, and
`status` sorts the obligations of a record with a pending head. The 0.73.3 release decided this behavior. The
adjustment function of the test held only the changes of 0.73.0.

The checks before the 0.73.3 pull request did not include this test module. The module reaches the changed code
through its fixtures and replays, not through an import of a changed module.

## What changed

- `tests/test_review_request_parity.py` adds the changes of 0.73.3 to its adjustment of the frozen report: the
  `review_task_pending` obligation, `slot_outcomes`, the obligation count, the sorted order of `status`, and the
  digest. The frozen request bytes do not change.

No module of the harness changed. No stored record changes, and no migration is necessary.

## Checks

- `test_review_request_parity` with the guidance, Codex, manifest and release-records modules: 104 tests pass on
  Python 3.12.8 and 3.9.6, with no skipped test. On 0.73.3 the parity test failed as it did in CI.
- Twelve test modules name the report fields that 0.73.3 changed, and the checks of 0.73.3 did not run them. On
  0.73.3 their 252 tests pass on Python 3.12.8, apart from the two failures of the parity test.
- `codex/generate.py --check` and `git diff --check` pass. No module of the harness changed.

CI on Python 3.9, 3.12 and 3.14 runs after the pull request opens.
