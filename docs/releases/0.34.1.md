# Exactory 0.34.1

This patch release includes the math-solver ranking validation and task recovery
fixes from [PR #12](https://github.com/exactory/exactory-client/pull/12).
Both the Claude Code and Codex plugin manifests identify version `0.34.1`, so
installations can distinguish this release from earlier `0.34.0` source.

## Fixes

- Non-object ranking JSON now produces a normal validation failure instead of
  an uncaught exception after recording a native intent.
- Task additions and completions acquire the native snapshot transaction lock
  before reading or writing tasks. Pending native intents and filesystem
  initialization block these writes, preserving the snapshot needed for
  unchanged-state recovery.
- The harness documentation explains how to stop dependent commands after a
  nonzero exit.

These fixes prevent the reported failure sequence. They do not repair an
already-blocked attack or permit ambiguous recovery. Read-only inspection,
ordinary task maintenance, research budgets, and provenance rules remain intact.

## Included controller features

This release also includes the persistent search controller and reviewed
finite-computation contracts described in the
[0.34.0 release notes](0.34.0.md). The follow-up features listed there under
"Still pending" remain pending in `0.34.1`.

## Upgrade

For Claude Code:

```sh
claude plugin marketplace update exactory-ai
claude plugin update exactory@exactory-ai
claude plugin list --json
```

For Codex:

```sh
codex plugin marketplace upgrade exactory-ai
codex plugin add exactory@exactory-ai --json
codex plugin list --marketplace exactory-ai --json
```

Preserve the existing installation scope. Confirm that the returned version
and the manifest at the installed path identify `0.34.1`, then start a new
session and review and trust changed hooks through the host's supported flow.
An update does not resume paused research, adopt attacks, or reset budgets.
The existing-attack and validation boundaries in the 0.34.0 notes still apply.

## Publication

The release tag is `exactory--v0.34.1`. The marketplace catalogs use the client
repository without a pinned tag. Publishing a source commit, publishing the
GitHub Release, and updating an existing installation are separate steps.
