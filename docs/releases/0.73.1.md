# Exactory 0.73.1

This release corrects the integrity step of `record-check`, which 0.73.0 added, and makes CI of 0.73.0 pass. The step
now reads only the artifacts of the store, and it counts the other file descriptors of the history instead of refusing
the record. The release follows 0.73.0. The work is recorded in
`misc/harness-improvement/20261104074403-harness-problems-closed-for-good` of the exactory repository.

## Why

After the release of 0.73.0, `record-check` ran on the 21 live research records. One deposited study failed the
`integrity` step with `invalid_input` ("Artifact reference is missing required fields"). Its history holds 214,020
descriptors that the publication scope wrote for files of the workspace (keys `media_type`, `path`, `projection` and
`sha256`, with a path relative to the workspace and no `size`). They are not artifacts of the store. The step read
every object with a path, a SHA-256 and a media type as an artifact reference, and the strict reader refused these for
the missing size. Two other studies hold no such descriptors.

## What changed

- The `integrity` step reads and verifies only references whose path is under the object directory or the sealed
  directory of the store (`research/sources/objects`, `research/sources/sealed`).
- Every other descriptor with a path, a SHA-256 and a media type is not read. The step result counts it as
  `workspace_descriptors`, next to `artifacts`, the count of verified artifacts.
- A store reference that lacks a field, or whose bytes differ from its digest, still fails the step.
- `docs/research-cli.md` states the corrected step.
- CI of 0.73.0 (run 41959274386) failed shard 0 on Python 3.9, 3.12 and 3.14 with no failing test: the test
  partition of CI fails on any skipped test, and the `/dev/null` sandbox test of `record-check` skipped where
  `sandbox-exec` does not exist. The test now checks the fallback there and returns, as its sibling test does,
  and it still runs the subprocess and the outside write under the real profile on macOS.
- `tests/incidents/ledger.json` has the entry `integration-record-check-workspace-descriptors` with tests of its real
  shape.

No route-pinned module changed. No stored record changes, and no migration is necessary. The review readers, the
requests and the reports of the other commands do not change.

## Checks

- The record check modules, the ledger, the output views, the check-mode audit, the Codex, manifest, guidance and
  release-records modules: 232 tests pass on Python 3.12.8 and 3.9.6. The new tests failed on 0.73.0 for the reason
  above, except the four that check the refusals that stay.
- The `/dev/null` sandbox test runs under the real profile on macOS, where `sandbox-exec` applies, and passes on
  both versions without a skip.
- On a copy of the deposited study, the integrity step passes with 4,758 verified artifacts and 11,478 workspace
  descriptors, and the reconstruction, authentication and continuation steps pass. Its report readers take longer
  than the default time budget of 900 s inside the check, so that copy needs `record-check --time-budget` with a
  larger value.
- `codex/generate.py --check` and `git diff --check` pass. No route-pinned module changed.

CI on Python 3.9, 3.12 and 3.14 runs after the pull request opens.
