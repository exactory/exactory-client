# Exactory 0.69.8

This patch makes the manuscript citation check read arXiv ids by the kind of identifier that carries them. BibTeX keys
no longer count as identifiers, and nothing inside another URL or DOI counts as an arXiv id.

## Why

The independent review of 0.69.7 found that its arXiv contexts were still substrings of the entry text. With an
unrelated title, each of these cited `arxiv:2609.14520v1`: the BibTeX key `arxiv:2609.14520`,
`doi={10.9999/arxiv:2609.14520}` and `url={https://example.org/arxiv.org/abs/2609.14520}`. The review also found that
0.69.7 no longer matched an unlabelled old-style id such as `hep-th/9304002`, which physics reference lists use.

## What changed

- The text of a BibTeX entry that the check reads leaves out the entry head with the key. This applies to DOI tokens
  and to arXiv tokens.
- URLs are parsed. A URL names an arXiv id only when its host is `arxiv.org`, `www.arxiv.org` or `export.arxiv.org`
  and its path is `/abs/`, `/pdf/`, `/html/` or `/format/` followed by the id, or the legacy
  `/ftp/<archive>/papers/<yymm>/<file>.pdf`. A URL on `doi.org` or `dx.doi.org` names its DOI. Any other URL names
  nothing.
- A DOI is read as one identifier. Only the DataCite DOI `10.48550/arXiv.<id>` names an arXiv id.
- In the text that remains without URLs and DOIs, an arXiv id is named by an `arXiv:` label, by a BibTeX `eprint`
  field, or, for an old-style id, by the id itself.
- DOI tokens keep their matching, and title matching does not change.

## Upgrade

- An entry whose only identifier is in its BibTeX key no longer cites the work by identifier. This also applies to
  DOIs.
- An arXiv id inside a URL on another host, or inside another DOI, no longer cites the work.
- An unlabelled old-style id, such as `hep-th/9304002`, cites the work again.
- A new-style id without `arXiv:`, an arxiv.org URL, the DataCite DOI or an `eprint` field still cites the work only
  by its title, as in 0.69.7.
- When an entry no longer cites a work, add an accounting item for that work, or write the identifier in one of the
  forms above. Publication bundles that are already recorded do not change. Problem citation exports do not change in
  this release.

## What stays the same

`find_citation_tokens`, the problem citation projection, DOI tokens, the end of an identifier, title matching, the
reviewer prompts, the route-pinned transport and cost modules and `review_state_evaluation.py` are unchanged.

## Checks

The new tests ran first against 0.69.7 and failed as expected (49 failed subtests in 32 tests). After the change, with
`PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=tests`, the modules `test_research_citation_accounting`,
`test_research_problem_citations`, `test_research_providers`, `test_research_publication`,
`test_research_publication_records`, `test_research_publication_files`, `test_research_problem_delivery`,
`test_math_problems_cli`, `test_codex`, `test_manifest` and `test_research_guidance` (381 tests) passed on Python 3.12.8
and 3.9.6. `codex/generate.py --check` and `git diff --check` pass.

## Corrections in 0.69.9

The independent review of this release found that it did not read each DOI as one identifier: it took URLs before
DOIs, so a URL inside a DOI counted, and a DOI stopped at `<`. Only `http` and `https` URLs counted as URLs, and
replacing URLs and DOIs with spaces joined text across them. A Markdown link to arxiv.org no longer cited the work.
Releases 0.69.9 and 0.69.10 find URLs of any scheme and DOIs in one pass and match labels in the original text
outside them.
