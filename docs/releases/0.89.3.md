# Exactory 0.89.3

This release corrects the tests that failed in the CI of 0.89.2. It follows 0.89.2. Only files under `tests/`
change, apart from the version and this note. The failure and the fix are recorded in
`misc/harness-improvement/20261113110022-every-open-record-and-review-capacity` of the exactory repository (lane
r0893-ci-fix).

## Why

The CI runs many test modules in one process for each shard. In 0.89.2, some tests changed the state of that shared
process and did not restore it, and the tests that ran after them in the same shard failed. About 3,000 distinct
tests in about 140 modules failed in the general shards on Python 3.9, 3.12 and 3.14. 1,509 of them failed with
`module 'research_harness.problem_claims' has no attribute 'initialize_problem'`, because a substitute module that a
fixture installed stayed in `sys.modules`. A failing module passed when it ran alone.

Each group of failures was traced to a test or a fixture. None was traced to the code of the harness, so the
harness that 0.89.2 installs works the same as the harness of this release.

## What changed

- The review helpers of `managed_strategy_fixtures` and `reviewer_fixtures` apply the synthetic binary backend of
  `visual_capacity_fixtures` only during one review, through the new `patch_bounded_binary_backend`. Before, they
  installed it on a case whose cleanups never ran, and the patches accumulated until Python reached its recursion
  limit.
- A test that sets up another fixture inside its own setup now registers the cleanup of that fixture before it runs
  the setup: `test_problem_post_head_planning`, `test_review_preflight`, `test_research_record_check`,
  `test_continuity_guard`, `test_capacity_signals` and `capacity_packet_fixtures`. When such a setup fails part way,
  its cleanup now removes the substitute claims module, the patches of the Codex runtime and its declarations, and
  the patch of the historical openness protocol that the setup installed.
- The reviewer child processes of `test_review_queue_triage` receive the test directory in `PYTHONPATH`. The CI
  discovery adds that directory only to the path of the parent process.
- One source-rule comparison in `test_session_rules_v3` declares a synthetic single-output profile. Under the
  default output profile, the harness correctly chose a multipart read for that review.
- The stored 0.87.0 openness fixtures of `unbound_packet_fixtures` declare the runtime and a keyed capacity prior of
  their archived synthetic executor. The archived files keep their bytes.
- One test of `test_automatic_gate_override` records a manuscript assignment after the managed helpers have run. It
  had passed only because the backend patch of an earlier review stayed installed. The test now installs that
  backend itself, on its own case.
- `tests/test_fixture_isolation.py` adds three tests: a managed research run, a failed nested review setup and a
  failed openness setup each leave the shared backends as they were. `test_review_queue_triage` adds a test that
  starts a reviewer child with an empty inherited `PYTHONPATH`. Each new test failed before its fix.
- Incident ledger entries `release-0892-shared-fixture-state` and `release-0892-synthetic-capacity-drift`.

## Checks

Before the pull request, the new and changed test modules passed on Python 3.12 and 3.9, and the math-solver harness
shard passed on Python 3.12 with the shard command of the CI (1,105 tests). The four general shards run with the
same command on Python 3.12 and 3.9 on a local machine and in the CI of the pull request, and the pull request
merges after its CI passes.

## Compatibility

No file of a reviewer route's runtime identity changes, so no route becomes stale. Stored records, packets, prompts
and requests keep their meaning and their digests.
