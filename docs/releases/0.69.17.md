# Exactory 0.69.17

This patch makes `minimum.text_priority` of an openness export name the full texts that the packet carries, and refuse
a listed version that has none, instead of stopping with an uncaught error.

## Why

`export_openness` named the first full-text capture of each listed version. A math-conjecturer record (on 0.69.6)
captured a GitHub manuscript twice: the raw `.tex` file, which was refused (`unexpected_mime`, no text), and then the
compiled PDF, which was extracted and read in full. Listing that version in `minimum.text_priority` stopped the export
with `TypeError: 'NoneType' object is not subscriptable`. With two available captures, the priority could also name a
body that the packet does not carry.

## What changed

- Each listed version expands, in list order, to every distinct extracted text of an available main full-text capture
  of that version that a required full reading pins and that the packet's evidence carries, in ascending SHA-256 order.
  The selection is the existing `openness_reading.list_reading_texts`.
- A listed version with no such text is refused with `openness_reading_gap` and details `{version_id}`. A repeated
  version is still refused with `invalid_input`.
- `docs/research-cli.md` states the contract.

## Upgrade

- An export whose listed versions each have one carried capture writes the same native packet bytes as 0.69.16. The
  tests compare with the function of 0.69.15, which 0.69.16 did not change.
- A version listed in `text_priority` that the packet does not read in full is now refused with `openness_reading_gap`.
  Remove it from the list, or record the full reading that the bound searches require.

## What stays the same

Only `export_openness` changes in production code. The selection of required readings, the evidence assembly, the
transport's handling of `text_delivery_priority`, the reviewer prompts and the route-pinned transport and cost modules
are unchanged.

## Checks

The new tests reproduced the `TypeError` before the change. After it, with `PYTHONDONTWRITEBYTECODE=1`, the modules
`test_research_problem_openness` (51 tests), `test_openness_reading_chain`, `test_problem_openness_source_delivery`,
`test_openness_final_turn` and `test_research_problem_openness_minimum` passed on Python 3.12.8 and 3.9.6, and so did
`test_research_problem_tools`, `test_codex`, `test_manifest` and `test_research_guidance` at 0.69.17.
`codex/generate.py --check` and `git diff --check` pass. The full suite runs in CI on the pull request.
