# Exactory 0.72.3

This release keeps the request memo of 0.72.2 to the argument types for which a kept request is exact. A history that
is not a plain list or tuple, and a fit order that is not a plain tuple of strings, now take the uncached path with the
original objects. The harness's own callers pass list histories and tuple orders, so their requests, reports and
refusals do not change. The release follows 0.72.2. The work is recorded in
`misc/harness-improvement/20261103225743-post-gate-rebuilds-every-review-request` of the exactory repository.

## Why

The independent code review of 0.72.2 (GPT 6 Astra at xhigh) found two minor defects in
`research_harness/review_request_evaluation.py` and no blocker or major defect:

- An iterator history was consumed while the key was built. The transport then built the request from the exhausted
  iterator, so the kept request missed the earlier messages, and a later call with the equal list received it too.
- The key turned the fit order into a tuple, so a list order shared the key of the equal tuple order. The transport
  treats them differently: it protects requested sources only when the order is `FIT_ORDER` itself. In the review's
  probe on a Codex route, the native body was 1,048,577 characters with the tuple order and empty with the list
  order, and the memo returned the tuple result for the list order.

## What changed

- `request_for_order` passes a history that is not a plain `list` or `tuple`, and an order that is not a plain
  `tuple` of plain `str`, unchanged to `review_transport.request_body` and keeps nothing.
- New tests: an iterator history, a list order after a warm tuple order, subclasses of the history and order types, a
  staged request built twice in one warm evaluation, the two retention counters after a refresh and after a
  runtime-scope clearing, and two independent evaluations that derive the same inputs twice.

No route-pinned module changed. No stored record changes and no migration is necessary.

## Checks

The tests of the two defects failed on 0.72.2 and pass after the change. The full suite and CI on every supported
version run after the pull request opens.
