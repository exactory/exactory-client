# Exactory 0.37.0

This release connects the shared research foundation introduced in 0.36.0 to the
actual shared and Codex skill workflows. It preserves the native mathematical
strategy reassessment and failed-method history from 0.35.0.

## Research workflow

Every shared skill and generated Codex entrypoint resolves the same
[research constitution](../../RESEARCH_CONSTITUTION.md). The new
[literature-review skill](../../skills/literature-review/SKILL.md) and
[managed workflow](../research-workflow.md) describe current acquisition, source
inspection, synthesis, prospective admission, research development, and review.

The cohort command freezes a definition; managed collection enumerates the actual
population. Every cohort abstract is read. The source network requires Tier 1 and
Tier 2 full reading, Tier 3 abstracts, and consequential full-source dependencies.
All five search purposes precede ideation, separately from within-field innovation
and five to ten distinct external original-paper studies. The complete objective
is fixed during literature synthesis and remains distinct from branch claims.

Experiments require a prospective cycle, pinned inputs, admission, and exact run
binding. Assessment and durable checkpoints retain negative outcomes, failed
branches, costs, and remaining obligations. Independent review of the actual
research candidate and a current whole readiness gate precede writing. Two
independent blind assessments of the exact manuscript remain a separate
publication requirement. Field standards, source support, scientific validity,
quantitative conditions, and uncertainty are retained without universal page,
citation, or research-cycle quotas.

## Reliability corrections

- Stage transitions validate source and destination requirements, including a
  proposed or inherited completed status. Enter unfinished work with pending status.
- Execution accounting retains known failure and timeout costs and leaves unknown
  or unreconciled usage pending. Worker observations seal the complete original
  output inventory before terminal publication; later byte changes cannot become
  current result evidence through reconciliation.
- Fresh verification work can acquire exact metadata before choosing its profile.
  The exact source/version and original body remain necessary for verification.
- A remote admission with no released start signal checks fresh current preparation
  before that first signal. Historical release records do not supply fresh permission.
- Native execution holds its validated common Store read and native writer lock
  through the actual execution token write and flush, then releases both before
  waiting or reconciliation. Competing common mutations can retry unchanged after
  that interval; receiver checks and mathematical acceptance remain separate.
- An interrupted study or draft initialization can retry its original request and
  arguments, repair the layout from current history, and preserve later state,
  context, literature, Git settings, and user files. Conflicting reuse and a new
  request to reinitialize an existing workspace remain refused.

## Distribution and validation

The distributed commands run from a workspace outside the plugin checkout,
including paths with spaces. Codex entrypoints resolve the shared policy and
workflow from their own installed location. Host hooks complement the checks
inside commands; they cover only tool events the host reports.

The CI matrix uses Python 3.9.25, 3.12.14, and 3.14.7 on Ubuntu 24.04, with pinned
checkout, Python setup, and Lean actions. It checks the paired marketplace,
generated entrypoints, complete Python source compilation, root and native suites,
Codex adapter coverage, JSON files, and the real Lean fixture. The Lean smoke tests
compile source independently of an existing fixture build cache.

Mechanical checks establish prerequisites, consistent bytes, and recorded
inspection. They do not establish comprehension, scientific truth, novelty,
social benefit, or a mathematical breakthrough. Native proof rules and independent
scientific assessment remain necessary.

## Upgrade and resume

Keep prior releases and local research history. An upgrade does not resume paused
work, reset a budget, or convert a historical receipt into current readiness.
Read `exactory-research status` and `next`, the search tree, checkpoint records,
pending admissions or remote intents, and the current gate before continuing.

Adopt legacy material explicitly and retain unresolved obligations. An existing
Store needing native rollback recovery requires `exactory-research recover`.
Historical native proposal schemas and terminal evidence continue to replay;
fresh work requires the applicable reviewed computation, foundation, and strategy
amendments. Reconcile retained runs and journals before new work. Unknown remote
outcomes remain pending until the supported reconciliation establishes what
happened. Research artifacts remain subject to the user's local-only storage policy.
