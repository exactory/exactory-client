# Exactory 0.64.1

This release repairs nine defects that a code review of the shipped 0.62.0
code found (G1 to G9), and gives every function that 0.61.0 and 0.62.0
added a name with a verb. The work is recorded in
`misc/harness-improvement/20261024163824-open-records-v13-v15-v16-v17`
of the exactory repository (`TASKS.md`, sections T5 and T6).

## Repairs

- G4 and G7, `status` and `next` of a study whose selected manuscript
  bundle is under measurement: the drift report compares each working file
  with the descriptor of its pinned artifact, size first and then a
  streamed SHA-256 with a fixed buffer. It no longer reads the pinned
  object, so a missing or corrupt pinned object does not stop `status`,
  and a large file is not held in memory. A missing, unreadable or unsafe
  working file keeps its code. With `--counters`, the evaluation
  diagnostics count the bytes hashed. `restore` still verifies every
  pinned object before it writes anything.
- G2, `restore`: each displaced working file is moved aside by a rename to
  a fresh name in its directory, and the backup artifact holds the bytes
  that were actually moved. The pinned bytes are installed by a link that
  fails when a file was created at the destination in the meantime. On a
  conflict, the restore stops with an error that lists every backup kept.
- G3, `restore`: two pinned paths whose components are equal after NFC
  normalization and case folding, or that name the same inode, are one
  destination. With different bytes the restore is refused before
  anything is written; with equal bytes they are restored once. On a
  case-sensitive filesystem, a bundle with two such paths and different
  bytes is therefore refused.
- G5, JATS XML: an unresolved entity reference anywhere, attribute values
  included, gives `xml_external_entity`, so a graphic name cannot
  disappear. DTD loading stays disabled.
- G6, JATS XML: graphic names are deduplicated with a set, and the parser
  has bounds on elements, depth, text size and time. A document past a
  bound gives a pending extraction with its own status.
- G1, format-only reruns: a format-only admission and its recording leave
  a closed cycle (`complete`, `failed` or `budget_paused`) closed. An
  ordinary admission after a conversion is still refused.
- G8, manuscript pin: every registry claim must be mapped before any
  evidence is compared, so a missing mapping is reported first.
- G9, format-only reruns: a converted output that equals an earlier output
  byte for byte is accepted before any JSON parsing.

Records and stores written by 0.61.0 to 0.64.0 stay readable with their
recorded results.

## Function names

These functions were renamed without a change of behavior (finding F10 of
the 0.61.0 review and the project rule that a function name contains a
verb): `fulltext.base_media_type` to `parse_base_media_type`,
`html_visuals._style_urls` to `_parse_style_urls`, `drafting._metadata` to
`_resolve_draft_metadata`, `drafting.draft_obligations` to
`find_draft_obligations`, `publication_files._working_file` to
`_read_working_file`, `publication_files.bundle_drift` to
`find_bundle_drift`, `publication_files._restore_path` to
`_validate_restore_path`, `codex/generate.py` `hook_command` to
`build_hook_command`, and the expat handlers of `_JatsArticle` to
`handle_start`, `handle_end`, `handle_characters`, `handle_default` and
`refuse_external_entity`. The JSON field `bundle_drift` of `status` keeps
its name. Sixteen test helpers were renamed in the same way. The module
docstring of `fulltext.py` is rewrapped to the line limit (finding F11).

## Not in this release

- The agent-facing texts of T13 (draft marker) and T16 (format-only
  reruns), and of the messages these repairs changed.
- The math-solver openness text priority, the AI Science lanes of 0.62.0
  that were not merged, and the store-latency change of v15 (0.65.0).
