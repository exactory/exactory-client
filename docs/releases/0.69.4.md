# Exactory 0.69.4

This patch fixes frozen record citations without a digest when a review received the record in more than one form.

## Why

On a copy of the unknotting record at revision 885, `value-review` refused both final result reviews for assignments
`assignment-result-a-r2-9` and `assignment-result-b-r2-8` with `review_evidence_undelivered` and `digest: null`.
About ten citations per review named records carried with a known digest in `problem_evidence` and without a digest
in earlier reviews' `material_objections` evidence. The old resolver treated the missing digest as another version.
The cited `problem_value problem-value-1` appeared only as equal projections without digests and was also refused.

## What changed

For a frozen record reference without a digest, one known carried digest selects a row with that digest, regardless
of copies without digests. If no carried digest is known, equal projection digests select the first matching row.
Two known digests, differing projections when no digest is known, and missing records remain refused.

## What stays the same

Explicit-digest resolution, current-record qualification, reviewer prompts, recorded packets and review contracts
are unchanged. The route-pinned transport and cost modules and `review_state_evaluation.py` are unchanged.
The change applies only to interpreting evidence the review already received and does not rewrite stored output.

The frozen caller audit covered review contract validation, recorded-review delivery audits and focused adjudication
validation through `review_supplied_evidence.undelivered_references`. Each checks content carried in frozen packets.
The new rules for a record reference without a digest apply to the first two. Focused adjudication validates its
evidence without review binding, so it refuses a record reference without a digest before resolution, and only
explicit-digest resolution applies there. `describe_version_evidence` uses current qualification and is unchanged.
This paragraph was corrected in 0.69.5. The earlier text said that the new rules apply to all three.

## Checks

The extended `test_review_frozen_record_evidence` module and the new final-review regression in
`test_problem_result_parts_continued` ran first after the fix: 16 tests passed on each Python, in 1.474 seconds on
Python 3.12.8 and 1.731 seconds on Python 3.9.6. The regression records a final result review through `value-review`
with both a mixed known/unknown-digest citation and a citation carried only as equal projections without digests.
Before the fix, the resolver tests rejected the supported cases and the final review reproduced
`review_evidence_undelivered` for `problem_openness`.

With `PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=tests`, these 17 modules passed on both Pythons, including all eight
modules found by searching `tests/` for `find_carried_record` or `review_evidence_undelivered`:
`test_problem_result_parts_continued`, `test_problem_result_parts`, `test_problem_result_contract`,
`test_research_problem_reviews`, `test_review_objection_identity`, `test_research_problem_objections`,
`test_research_problem_adjudication_resolution`, `test_review_result_descriptor_aliases`, `test_research_guidance`,
`test_codex`, `test_manifest`, `test_problem_result_reassessment_binding`, `test_research_frozen_record_refusal`,
`test_research_review_delivery`, `test_review_frozen_record_evidence`, `test_visual_contract_integration` and
`test_visual_result_delivery`. Each run passed all 434 tests with no failures, errors or skips: 557.647 seconds on
Python 3.12.8 and 640.601 seconds on Python 3.9.6.

`codex/generate.py --check` and `git diff --check` passed. The explicit-digest branch and all seven protected modules
were also compared with `a0969b4` and remain byte-for-byte unchanged. All other protocol definitions and the current
lookup logic retain the same syntax trees, apart from the shortened lookup docstring. The full suite and the
original revision-885 store were not run; the existing result-series fixture supplies the regression.
