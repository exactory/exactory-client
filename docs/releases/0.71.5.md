# Exactory 0.71.5

This patch makes the file guard's discovery checks read the file status themselves, so that a check that fails
still denies the tool call on Python 3.14. It completes the policy of 0.71.4 on every supported interpreter.

## Why

The CI run of 0.71.4 failed on Python 3.14 only: the four tests that put a directory with mode `000` in the path of
a workspace, output-view, shell-word or controller check saw the guard allow the call instead of denying it.

From Python 3.14 on, `pathlib.Path.exists()`, `is_file()`, `is_dir()` and `is_symlink()` return `False` on every
`OSError` from the operating system (the pathlib reference, "Querying file type and status", changed in version
3.14). Up to 3.13 they raised every `OSError` except `ENOENT`, `ENOTDIR`, `EBADF` and `ELOOP`. The guard and the
controller discovery relied on that earlier behaviour: a `PermissionError` while probing `problem.json`, an
output-view marker or `.search/tree.json` reached the explicit denial through the exception boundaries of 0.71.4.
On 3.14 the same probe answered "absent", and the call went through.

## What changed

`hooks/math_search.py` gains `path_exists`, `is_regular_file`, `is_directory` and `is_symlink`, which call
`os.stat` and keep the pre-3.14 distinction on every version: an absent path (`ENOENT`, `ENOTDIR`, `EBADF`,
`ELOOP`, or a path the OS cannot represent) is `False`, and any other failure raises. `discover` and
`workspace_for` use them. `hooks/guard_attack_files.py` uses them in the output-view discovery
(`_has_output_views`).

The three exception boundaries of 0.71.4 are unchanged: `ENAMETOOLONG` still skips the word or treats the target
as outside the guarded files and folders, and every other `OSError` still reaches the explicit check-failure
denial. The controller check and its error boundary are unchanged. There are no record, route, stored contract or
pinned module changes: the hooks are not part of the controller digest, and the route-pinned modules are untouched.

## Upgrade

No action is necessary.

## Checks

The four permission tests of 0.71.4 fail on the unpatched hook under Python 3.14.6 and pass on the patch under
3.14.6, 3.13.8, 3.12.8 and 3.9.6. A new test pins the semantics of the four status checks directly: absent paths,
files, directories, symlinks, an unrepresentable path, an overlong component (`ENAMETOOLONG`) and a directory
without permissions (`PermissionError`). The hook test modules, the version, manifest and release-note tests,
`codex/generate.py --check` and `git diff --check` pass.
