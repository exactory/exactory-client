# Exactory 0.76.0

This release makes the files that the harness owns read-only on disk. It is the third release of the open items
after 0.73.6, and it follows 0.75.0. The work is recorded in
`misc/harness-improvement/20261105155433-open-items-after-0-73-6` of the exactory repository. The approach is the
owner's decision of 2026-10-01. GPT 6 Astra at effort `ultra` set its scope and made it a release of its own.

## Why

- The plugin hooks read each shell command and refuse a direct write to a harness-owned file, for example to the
  journal of an attack. Three review rounds before release 0.50.1 showed that a reading of shell text cannot follow
  every form that the shell runs.
- As a result, a direct write by an agent, such as `echo x >> journal.jsonl`, can change a file that only a native
  command is permitted to write.

## What changed

- One writer, `research_harness/native_writes.py`, publishes a harness-owned file atomically. It writes a temporary
  file in the same directory, sets the final mode, syncs the file, renames it over the target and syncs the
  directory. An interruption before the rename leaves the previous file intact.
- Every native writer of a harness-owned file uses it, under the lock that the writer already takes. This covers the
  attack files of the math-solver harness, the controller store and its views, the run files, the activity log of
  the hook, and the projections, output views, native exports, reviewer packets and literature exports of the
  research harness. An append reads the file, extends it and replaces it under that lock.
- The reports of `exactory-check lookup` and `exactory-derive`, the citation cache, the authorship record of the
  paper hook and the counter of the autopilot hook are published the same way. A reader of the authorship record
  sees the previous record or the new one, and never a partial file.
- A harness-owned file ends with mode `0400`. A shell redirection or a Python `open` for writing or appending then
  fails with a permission error. The native commands and hooks update the files as before.
- The files that agents write by design stay writable: `problem.json`, `novelty.md`, `preconditions.json`,
  `ranking.json`, the study files, `units/INVENTORY.md`, the unit files, the bibliography, and the work files of an
  owned probe. The input and build copies of a run keep their recorded modes, and the artifact objects of the
  research store keep their mode `0444`. Lock files and SQLite databases do not change.
- Readers do not require the read-only mode. A record written before this release reads, replays and plans as
  before. The next native write of one of its writable files publishes the file again read-only, also when its bytes
  do not change.
- This protects against accidental direct writes only. The same user can still change the mode, or remove or
  replace a file through its writable directory. Full protection needs host-enforced read-only access with a
  separately authorized writer, which this repository does not establish. The hooks and their shell-reading guards
  stay as they are.
- The managed Codex hook runtime of 0.75.0 does not change, so its pending administrator install is not affected.
- The math-solver, math-conjecturer, ai-science and write skills, `docs/research-cli.md` and
  `docs/research-workflow.md` state which files are read-only and what the mode stops. They tell an agent what to do
  when a direct write fails with a permission error. The agent uses the command that owns the file, leaves the file
  of a hook to that hook, and never changes the mode of a harness-owned file.
- The regression ledger has one new `real_shape` entry, `h15-accidental-direct-write-protection`, with 16 tests.

The content of stored records does not change, and no migration is necessary. A writable file of an earlier record
becomes read-only at its next native write.

## Checks

- On the native-writer change, the whole suite (471 test files, 7,688 tests per Python) ran on Python 3.12.8 and
  3.9.6. Its only failures were 19 tests in five modules whose fixtures wrote a file that is now read-only. These
  fixtures now write as the harness or a deliberate tamperer does, and their assertions are unchanged.
- After the last code change, 26 test modules pass on both Pythons with 825 tests each. They cover every changed
  test module and every module that names a changed file in its text or fixtures. The text, version, registry and
  ledger modules are among them. After the last texts, the 10 modules that read the changed texts pass on both
  Pythons with 228 tests each.
- On an attack that the CLI created, a shell redirection to `journal.jsonl`, the same redirection after `cd`, and a
  Python append fail with a permission error. `problem.json` and `novelty.md` stay writable. The activity hook, run
  as Claude Code runs it, appends its entry on both Pythons and leaves `activity.jsonl` read-only.
- Compile on both Pythons, `codex/generate.py --check` and `git diff --check` pass. The eleven protected modules,
  the fit orders and `hook_runtime/` are unchanged.
- Since 0.75.0, `main` also holds pull request #119. CI of 0.75.0 failed on a test that pinned the 0.73.6 bytes of
  `ci/record_fingerprint.py`, and #119 pins its 0.75.0 bytes. The 0.74.1 and 0.75.0 versions of that script give
  equal output on copies of 21 records.
- The texts were written by Fable 5.1 and reviewed once by Astra 6 at `max`. Its six findings, two major and four
  minor, are applied.
