# Exactory 0.72.4

This release makes the request memo of 0.72.2 call `review_transport.request_body` with the same arguments as the
pinned `list_built_requests`: no order for the current fit order, and the order as the fifth positional argument for
an earlier one. The requests, reports and refusals do not change. The release follows 0.72.3. The work is recorded in
`misc/harness-improvement/20261103225743-post-gate-rebuilds-every-review-request` of the exactory repository.

## Why

CI of 0.72.2 on `main` (run 41792031568) failed on Python 3.14.7 general shards 0, 1 and 2 with 17 errors and 1
failure. Several existing tests replace `review_transport.request_body` with a function that has no `order`
parameter, and the memo passed `order=` on every call. The replacement raised `TypeError`. Authentication counts
that as a failed check, so `test_problem_result_contract` reported `review_bar_pending`. One more test counted calls
of `list_built_requests`, which `build_assignment_request` no longer calls.

The real `request_body` accepts `order=`, so 0.72.2 and 0.72.3 build the same requests as 0.72.1. The parity suite
and the comparison on the record copy show this.

## What changed

- `research_harness/review_request_evaluation.py` calls `request_body` through one helper that passes the arguments
  of the pinned iterator, on the cached path and on both uncached paths.
- `test_review_scoped_preparation_v2` counts calls of `request_body`, with the same intent: each new preparation
  derives the request again, and two builds inside one preparation share one derivation.
- New tests: a four-parameter replacement of `request_body` works through `build_assignment_request` and
  `authenticate_provenance`, and the argument shape is the pinned one on every path.

No route-pinned module changed. No stored record changes and no migration is necessary.

## Checks

The new tests failed on 0.72.3 and pass after the change. Before the repeated call was folded into one helper,
the 76 test modules that mention `request_body`, `list_built_requests`, `build_assignment_request`,
`authenticate_provenance` or `authenticate_attempt`, with the parity, manifest, Codex and guidance modules (1,165
tests), passed on Python 3.12.8, 3.9.6 and 3.14.6. After it, the modules of the CI failure, the parity suite and
the request tests (153 tests) pass on the same three versions. The full suite and CI on every supported version
run after the pull request opens.
