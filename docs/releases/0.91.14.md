# Exactory 0.91.14

This release repairs two tests that failed in CI since 0.91.11. It changes no file of `research_harness` and no
command of the harness. The release follows 0.91.13.

## What changed

- `tests/fixtures/capacity_transport_inventory.json` holds a checksum for each function that admits a reviewer
  call. Release 0.91.11 changed `_invoke_once` and `invoke_assignment` of `research_harness/review_protocol.py`,
  and it did not renew their two checksums. The test `test_source_calls_are_budgeted_and_new_call_sites_fail` of
  `tests/test_capacity_guard.py` failed for that reason.
- The two changes of 0.91.11 add no reviewer call and change no admission. In `_invoke_once`, the block that owns
  the transport processes moved inside the `try` block. In `invoke_assignment`, the read of the assignment waits
  for a busy store, and the refusal record returns its record. The two checksums now follow the source.
- The test `test_unsealed_historical_observation_keeps_receipts_but_is_pending_for_readiness` of
  `tests/test_research_gates.py` builds an observation without a seal. It did so with a patch of
  `execution.prepared_mutation`. Since 0.91.11, the record of an observation goes through
  `prepared_task_mutation`. The patch had no effect, the observation kept its seal, and the test failed.
- The test now patches `prepared_task_mutation`. The readiness gate did not change. It reports
  `execution_output_seal_required` for an observation without a seal, as before.

## Effects and limits

- The harness behaves as in 0.91.13.
- The releases 0.91.11, 0.91.12 and 0.91.13 were merged while these two tests failed. The must-pass runs of
  0.91.11 and 0.91.12 did not hold the two modules. The command `ci/must_pass.py` of 0.91.13 holds
  `test_capacity_guard` among the pins of the harness code.

## Compatibility

- No stored record and no reviewer route is affected.

## Checks

The two tests fail on 0.91.13 and pass with this release on Python 3.12 and 3.9. The version tests were still
running when the pull request was merged. `codex/generate.py --check` and `git diff --check` passed.

The CI of the pull request runs the full suites on Python 3.9, 3.12 and 3.14, in eight shards for each version.
