# Exactory 0.46.0

This release corrects two faults that stopped a study during literature
preparation. It changes no stored record and no research gate.

## Full-text capture accepts originals up to 128 MiB

The HTTP client kept each response body in memory up to 32 MiB. A larger
response failed with `response_too_large`. Many arXiv PDFs with large figures
are bigger than 32 MiB. For example, `arxiv:2512.19791v1` is 47 MB, so a study
could not capture it and could not read it in full.

The default bound is now 128 MiB (`DEFAULT_MAX_RESPONSE_BYTES` in
`research_harness/http.py`). A response that declares more than 128 MiB, or
sends more than 128 MiB, still fails with `response_too_large`. The capture
keeps the exact original bytes and their hash, as before. The total time limit
of one request stays at 120 seconds.

## Mapped imports keep the date of every record

`exactory-research import-response` with `web` or `mcp` mappings failed with
`TypeError: 'str' object is not callable` when two or more mappings carried
`publication_date`. The date of the first record replaced the function that
reads each mapped field. The function now has its own name, and every record
keeps its publication date.

A study that met this fault can import the same saved response again with its
dates. Earlier imports without dates stay valid.
