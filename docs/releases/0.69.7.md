# Exactory 0.69.7

This patch replaces the arXiv id boundary of 0.69.6 in the manuscript citation check with a list of arXiv reference
contexts. It also closes a gap in the ambiguity check of problem citation links.

## Why

The independent review of 0.69.6 found three defects.

- The 0.69.6 boundary still let an arXiv id match inside unrelated text. Each of `doi={10.9999/x:2609.14520}` (also
  with `;` or parentheses), the BibTeX key `ref:2609.14520`, `https://notarxiv.org/abs/2609.14520` and
  `doi={10.9999/x10.48550/arxiv.2609.14520}` cited `arxiv:2609.14520v1`. The accounting could then pass an uncited
  work.
- The 0.69.6 boundary no longer matched the legacy URL `https://arxiv.org/ftp/arxiv/papers/2006/2006.11098.pdf`.
- 0.69.6 found the arXiv families of a work only from its id and its DOI aliases. A work with the DataCite DOI of one
  paper and a plain arXiv alias of another paper was linked to the first paper.

## What changed

- An arXiv id in a bibliography cites a work only right after one of these contexts:
  - `arXiv` as a word, then `:` or a space;
  - an arXiv URL whose host is `arxiv.org`, `www.arxiv.org` or `export.arxiv.org`, with the path `abs/`, `pdf/`,
    `html/`, `format/` or `ftp/<archive>/papers/<yymm>/`;
  - the DataCite DOI prefix `10.48550/arXiv.`;
  - a BibTeX `eprint` field.
- DOI matching and title matching do not change.
- The citation projection of a problem finds the arXiv families of a work from its id and every alias. It links the
  work to an earlier citation only when exactly one family results and the work id or a DOI alias gives it.

## Upgrade

- Manuscript citation accounting: an entry that gives an arXiv id in no such context, for example a bare id in a note,
  no longer cites the work by identifier. The entry still cites the work when the titles match. Otherwise add an
  accounting item, or write the id as `arXiv:<id>`, as an arxiv.org URL, as the DataCite DOI or in an `eprint` field.
- An entry that matched only through an unrelated identifier no longer cites the work. Add an accounting item for that
  work. The 0.69.6 note on items that are refused as `already_cited` still applies. Publication bundles that are
  already recorded do not change.
- Problem records: the citation list is part of the problem evidence digest. The list can differ between 0.69.4 and
  0.69.7 for a record that read one paper under its arXiv id and its DataCite DOI, or that holds a work with a plain
  arXiv alias or with arXiv aliases of two papers. If such a record has recorded result reviews and is not posted, run
  both result reviews again, record a new post decision and export again. Posted problems, stored reviews and exports
  do not change.

## What stays the same

DOI tokens, the end of an identifier, title matching, the DataCite rule of 0.69.5 for problem citations, the reviewer
prompts, the route-pinned transport and cost modules and `review_state_evaluation.py` are unchanged.

## Checks

The new tests ran first against 0.69.6 and failed as expected (36 failed subtests: unrelated text cited the works, the
legacy FTP URL did not, and a work with arXiv aliases of two papers was linked). After the change, with
`PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=tests`, the modules `test_research_citation_accounting`,
`test_research_problem_citations`, `test_research_providers`, `test_research_publication`,
`test_research_publication_records`, `test_research_publication_files`, `test_research_problem_delivery`,
`test_math_problems_cli`, `test_codex`, `test_manifest` and `test_research_guidance` (376 tests) passed on Python 3.12.8
and 3.9.6. `codex/generate.py --check` and `git diff --check` pass.
