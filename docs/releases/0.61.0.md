# Exactory 0.61.0

This release repairs full-text capture and review delivery and lets a session
started for one assignment stop inside an autopilot study. The work comes from
records v13 and v16 in `misc/harness-improvement/` of the exactory repository.
The implementation and review decisions are recorded in
`misc/harness-improvement/20261024163824-open-records-v13-v15-v16-v17`,
sections T2 and T3 of `TASKS.md`.

## PDFs served as generic binary

The PubMed Central open-data bucket on Amazon S3 serves article PDFs as
`binary/octet-stream`, the S3 default media type. The harness now treats it
like `application/octet-stream`. The set `GENERIC_BINARY_MEDIA_TYPES` in
`research_harness/fulltext.py` holds both types. Every decision that accepts
a generic binary response or infers a PDF from its bytes uses that set.

For full-text extraction, a generic binary body that starts with `%PDF-` is
handled as a PDF. A body without that signature stays unsupported. The capture
records the reported media type unchanged. The extraction records the type
`application/pdf` and the format decision `pdf_signature_from_generic_binary`.
The stored S3 PDF from study 2601.01283 extracts with 9 pages and that decision.

## Review delivery and media-type spellings

The projection reconstructs which evidence an actual or recorded review request
delivered. It calls `review_transport.is_binary_evidence` and
`fulltext.detect_media_type` with the same reported type and bytes as
construction. A type such as `Binary/Octet-Stream` or `Application/PDF` is
projected as construction sent it, with the reported descriptor unchanged.

Request construction keeps its 0.60.1 behavior for every spelling apart from
the new `binary/octet-stream` alias. Every module whose bytes enter a review
route's runtime or a profile is byte-identical to 0.60.1, so earlier reviews
still authenticate. Rebuilds preserve the original media spelling, including
`image/PNG` in image data URLs.

Media-type checks for parsing, extraction and byte validation use
`fulltext.base_media_type`. It lowercases the base type and removes parameters
and surrounding spaces. These checks include HTML and PDF extraction,
visual-asset validation, and `import-response` admission and JSON parsing.
They also include HTML and PDF locators, HTML asset inventories, component
page maps, refusal evidence checks and scientific source-component validation.

For `web` and `mcp` imports, `import-response` stores the exact response bytes
under the declared media type. The stored response descriptor retains that
spelling.

A declared type that the artifact descriptor grammar refuses, such as
`" application/json "` or `"application/json ; charset=utf-8"`, is refused as
`invalid_import` before anything is recorded.

## The article body of a PubMed Central page

The HTML extractor recognizes the class `main-article-body` as article body.
A reference list with class `ref-list` stays in the extracted text and does
not count as body content, as an arXiv bibliography already does. Abstracts,
headings and metadata still do not count as body content.

The stored PubMed Central page from study 2601.01283 extracts with the headings
"2. Results and Discussion" and "3. Conclusion". All 40 references stay in the
text after the conclusion, and none counts as body content.

## Sessions started for one assignment

A nonempty `EXACTORY_ASSIGNED_SESSION` marks a session started for one
assignment inside a study. The autopilot Stop hook reads its payload, then
lets the marked session stop without reading or changing
`.exactory/autopilot_count`. An absent counter stays absent. Claude Code and
Codex behave the same way.

A session without the marker continues as before. The hook asks it to continue
while the study is on autopilot, is not at stage `complete` and has no `waiting`
reason. The existing cap still applies. `skills/ai-science/LOOP.md` and the
README's environment table describe the marker and those conditions. The hook
tests remove the runner's `EXACTORY_ASSIGNED_SESSION` and
`EXACTORY_AUTOPILOT_MAX` values or set their own values explicitly.

## The request budget of a full-text capture

The `fulltext` row of `docs/research-cli.md` now states that each redirect and
each retry counts against `max_requests`. A link with three redirects before
the PDF needs four attempts. When the budget runs out, the capture stays in
the record as `pending`, with `extraction_status` equal to `request_budget`.
A new `fulltext` request with its own request id and a larger `max_requests`
tries again. This documentation change describes the existing behavior.

## Known limitation

A request recorded by 0.60.0 or earlier can contain PDF bytes reported as
`binary/octet-stream` that it delivered as UTF-8 text. A recheck now counts
that evidence as not delivered, and a rebuild attaches the PDF. Version
0.60.0 accepted such text delivery only if every byte was valid UTF-8.
Version 0.58.0 already applied the same attachment rule to
`application/octet-stream` PDFs. None of the 319 local stores holds such a
request.
