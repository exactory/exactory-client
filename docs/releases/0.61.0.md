# Exactory 0.61.0

This release repairs full-text capture and review delivery and lets a session
started for one assignment stop inside an autopilot study. The work comes from
records v13 and v16 in `misc/harness-improvement/` of the exactory repository.
The implementation and review decisions are recorded in
`misc/harness-improvement/20261024163824-open-records-v13-v15-v16-v17`,
sections T2 and T3 of `TASKS.md`.

## PDFs served as generic binary

The PubMed Central open-data bucket on Amazon S3 serves article PDFs as
`binary/octet-stream`, the S3 default media type. The harness now treats it
like `application/octet-stream`. The set `GENERIC_BINARY_MEDIA_TYPES` in
`research_harness/fulltext.py` holds both types. Every decision that accepts
a generic binary response or infers a PDF from its bytes uses that set.

A generic binary body that starts with `%PDF-` is handled as a PDF. A body
without that signature stays unsupported for full-text extraction. The capture
records the reported media type unchanged. The extraction records
`application/pdf` and `pdf_signature_from_generic_binary` as its format decision.
The stored S3 PDF from study 2601.01283 extracts with 9 pages and that decision.

## Review delivery and media-type spellings

The projection reconstructs which evidence an actual or recorded review request
delivered. It now calls request construction's own decision functions. A type
such as `Binary/Octet-Stream` or `Application/PDF` is projected as construction
sent it, with the reported descriptor unchanged.

Request construction keeps its 0.60.1 behavior apart from the generic binary
change above. Every module whose bytes enter a review route's runtime is
byte-identical to 0.60.1, so earlier reviews still authenticate.

Decisions outside review delivery compare the base media type with
`fulltext.base_media_type`, which lowercases it and removes parameters. These
include the extractor's HTML and PDF checks, visual-asset validation, and the
admission and JSON parsing of `import-response`.

## The article body of a PubMed Central page

The HTML extractor recognizes the class `main-article-body` as article body.
A reference list with class `ref-list` stays in the extracted text and does
not count as body content, as an arXiv bibliography already does. Abstracts,
headings and metadata still do not count as body content.

The stored PubMed Central page from study 2601.01283 extracts with the headings
"2. Results and Discussion" and "3. Conclusion". All 40 references stay in the
text after the conclusion, and none counts as body content.

## Sessions started for one assignment

A nonempty `EXACTORY_ASSIGNED_SESSION` marks a session started for one
assignment inside a study. The autopilot Stop hook reads its payload, then
lets the marked session stop without reading or changing
`.exactory/autopilot_count`. An absent counter stays absent. Claude Code and
Codex behave the same way.

A session without the marker continues as before. The hook asks it to continue
while the study is on autopilot, is not at stage `complete` and has no `waiting`
reason. The existing cap still applies. `skills/ai-science/LOOP.md` and the
README's environment table describe the marker and those conditions. The hook tests
remove the runner's `EXACTORY_ASSIGNED_SESSION` and `EXACTORY_AUTOPILOT_MAX`
values or set their own values explicitly.

## The request budget of a full-text capture

The `fulltext` row of `docs/research-cli.md` now states that each redirect and
each retry counts against `max_requests`. A link with three redirects before
the PDF needs four attempts. When the budget runs out, the capture stays in
the record as `pending`, with `extraction_status` equal to `request_budget`.
A new `fulltext` request with its own request id and a larger `max_requests`
tries again. This documentation change describes the existing behavior.

## Known limitation

A request recorded by 0.60.0 or earlier can contain PDF bytes reported as
`binary/octet-stream` that it delivered as UTF-8 text. A recheck now counts
that evidence as not delivered, and a rebuild attaches the PDF. Version
0.60.0 accepted such text delivery only if every byte was valid UTF-8.
Version 0.58.0 already applied the same attachment rule to
`application/octet-stream` PDFs. None of the 319 local stores holds such a
request.

## Tests

`tests/test_research_fulltext.py` adds these tests:

- `test_binary_octet_stream_requires_a_pdf_signature_for_extraction`
  checks that both generic binary types require the PDF signature for extraction.
- `test_generic_binary_media_spellings_detect_only_pdf_signatures`
  checks type case and parameters in signature detection.
- `test_generic_binary_media_spellings_extract_pdfs_and_keep_non_pdf_reports`
  checks extraction and preservation of the reported type for unsupported bodies.
- `test_declared_pdf_media_spellings_extract_without_rewriting_the_reported_type`
  checks declared PDF types without changing their reported spelling.
- `test_pmc_main_article_body_retains_references_without_counting_them_as_body`
  checks the article body, reference retention and reference-only landing pages.

The last test uses the authored fixture
`tests/fixtures/research/pmc-main-article-body.html`. It also checks that a page
with only references stays a landing page.

`tests/test_research_binary_pdf.py` adds these tests:

- `test_binary_octet_stream_acquisition_preserves_reported_type_and_original`
  checks response acceptance, the original bytes and the reported media type.
- `test_stored_binary_octet_stream_pdf_uses_only_a_successful_captured_page_map`
  checks that PDF locators require a successful captured extraction and stay
  within its page bounds.
- `test_stored_pdf_media_spellings_use_the_same_captured_page_map`
  checks those locators across type case and parameters without changing the capture.

`tests/test_review_generic_binary_pdf.py` adds these tests:

- `test_binary_octet_stream_pdf_is_withheld_on_a_text_only_route`
  checks omission of PDF bytes on a text route.
- `test_binary_octet_stream_pdf_is_attached_as_pdf_without_relabeling_its_descriptor`
  checks exact PDF attachment bytes and the unchanged artifact descriptor.
- `test_generic_binary_media_spellings_agree_from_construction_through_projection`
  checks construction and projection for both generic binary types.
- `test_declared_pdf_media_spellings_agree_from_construction_through_projection`
  checks that agreement for declared PDF types.
- `test_image_media_spellings_agree_from_construction_through_projection`
  checks that agreement for image types.

`tests/test_review_input_projection.py` adds these tests:

- `test_binary_octet_stream_pdf_requires_exact_native_attachment_bytes`
  checks that inline PDF text does not count as a native attachment.
- `test_binary_octet_stream_text_requires_matching_descriptor_and_non_pdf_bytes`
  checks exact UTF-8 delivery of a generic binary body without a PDF signature.
- `test_native_attachment_media_spellings_match_without_relabeling_the_descriptor`
  checks attachment matching while the descriptor stays unchanged.
- `test_visual_png_media_spellings_preserve_exact_images_and_descriptors`
  checks exact visual inputs and their descriptors across media-type spellings.

`tests/test_review_frozen_pdf_capture.py` adds these tests:

- `test_stored_generic_binary_pdf_without_frozen_inference_is_not_a_locator_refusal`
  checks that missing frozen format inference does not become a locator refusal.
- `test_generic_binary_media_spellings_do_not_invent_a_frozen_pdf_page_map`
  checks that type case and parameters do not supply a missing page map.

`tests/test_research_public_source_delivery.py` adds these tests:

- `test_stored_binary_octet_stream_pdf_delivers_its_exact_source_jpeg_component`
  checks the bytes and provenance of a JPEG component of a stored PDF.
- `test_pdf_media_spellings_deliver_source_components_without_relabeling_captures`
  checks that source-component delivery preserves the capture's reported type.

`tests/test_stop_cap.py` adds these tests for both hosts:

- `test_assigned_session_preserves_counter`
  checks that nonempty markers leave the counter's bytes unchanged.
- `test_assigned_session_leaves_counter_absent`
  checks that a marked session does not create a counter.
- `test_unassigned_session_advances_counter`
  checks that an absent or empty marker still permits the existing advance.

`tests/test_hooks.py` also removes the runner's marker and autopilot cap from
the hook environment. The current-version pins in `tests/test_codex.py`,
`tests/test_manifest.py` and `tests/test_research_guidance.py` now name 0.61.0.
The guidance test also requires `docs/releases/0.61.0.md`.
