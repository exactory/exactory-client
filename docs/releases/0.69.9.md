# Exactory 0.69.9

This patch makes the manuscript citation check find URLs and DOIs in one pass, so that no identifier counts inside
another, and credit `arXiv:` labels, `eprint` fields and old-style ids only outside URLs and DOIs.

## Why

The independent review of 0.69.8 found that, with an unrelated title, each of these still cited `arxiv:2609.14520v1`:

- `doi={10.9999/https://arxiv.org/abs/2609.14520}`, because 0.69.8 took URLs before DOIs;
- `doi={10.9999/<arxiv:2609.14520>}`, because a DOI stopped at `<`;
- `url={ftp://example.org/?q=arxiv:2609.14520}`, because only `http` and `https` URLs counted as URLs;
- the plain-text reference `[1] arXiv:10.9999/nope 2609.14520`, because 0.69.8 replaced URLs and DOIs with spaces and
  so joined `arXiv:` to an unrelated number.

The review also found that a Markdown link `[U](U)` with an arxiv.org URL no longer cited the work.

## What changed

- URLs of any scheme and DOIs are found in one pass from left to right. The identifier that starts first wins, and an
  identifier inside it does not count. A URL ends at `]`, and a DOI keeps `<` and `>`, which legacy SICI DOIs use.
- A URL names an arXiv id only on `arxiv.org`, `www.arxiv.org` or `export.arxiv.org` with an arXiv path, as in 0.69.8.
  A DOI names an arXiv id only when it is `10.48550/arXiv.<id>`.
- `arXiv:` labels, `eprint` fields and old-style ids are matched in the original text, and count only when they do not
  overlap a URL or a DOI. Nothing is replaced, so no text is joined.
- DOI tokens, BibTeX keys (left out since 0.69.8), title matching and `find_citation_tokens` do not change.

## Upgrade

- An arXiv id inside another identifier no longer cites the work. A Markdown link to arxiv.org cites it again.
- Since 0.69.8, an entry whose only identifier is in its BibTeX key does not cite the work by identifier. This also
  changes the lineage check of publication preparation: a required work that only an entry key named is reported as
  `lineage_citation_missing`, and an accounting item does not satisfy that check. Put the identifier in a `doi`, `url`
  or `eprint` field, or give the exact title. Publication bundles that are already recorded do not change.
- A DOI token still matches inside a publisher URL path, for example `link.springer.com/article/10.1007/...`, as
  before.

## What stays the same

The problem citation projection, the reviewer prompts, the route-pinned transport and cost modules and
`review_state_evaluation.py` are unchanged.

## Checks

The new tests ran first against 0.69.8 and failed as expected (18 failed subtests). After the change, with
`PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=tests`, the modules `test_research_citation_accounting`,
`test_research_problem_citations`, `test_research_providers`, `test_research_publication`,
`test_research_publication_records`, `test_research_publication_files`, `test_research_problem_delivery`,
`test_math_problems_cli`, `test_codex`, `test_manifest` and `test_research_guidance` (388 tests) passed on Python 3.12.8
and 3.9.6. `codex/generate.py --check` and `git diff --check` pass.
