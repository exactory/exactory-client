# Exactory 0.56.0

This release gives a Claude Code session its own reviewer route, so that the
independent reviews of a record run inside the session that opened it, and it
ships the repairs that the first problem record exercised on 2026-10-20 and
2026-10-21 (`misc/harness-improvement/v19` of the exactory repository). The
record kinds of 0.55.1 are unchanged. The version 2 result prompt changes; the
bar, slate, native and adjudicator prompts are unchanged.

## The Claude Code reviewer route

- `review-route` accepts `adapter: "claude_cli_v1"` at `endpoint:
  "claude://local"` with `configuration: {effort, max_output_tokens,
  timeout_seconds}`. `effort` is `low`, `medium`, `high`, `xhigh` or `max`;
  `timeout_seconds` is at most 3600.
- Each invocation runs `claude -p` as its own process in an empty working
  directory: safe mode (no CLAUDE.md, skills, plugins, hooks, MCP servers or
  auto memory), no built-in tools, a system prompt replaced by the canonical
  review prompt, no session persistence and no permission prompts. The packet
  goes in as one stream-json user message that the CLI echoes back.
- The adapter verifies the observed stream, never the reviewer's self-report:
  one session initialization that reports no tools, MCP servers, skills or
  commands and the configured model; the echoed input equal to the request; no
  tool use, tool result, hook output, compaction, injected input or second
  turn; one successful result whose text equals the assistant output; a
  control string written to the working directory absent from every event.
- The recorded runtime names the isolation flags and the input contract. The
  installed CLI version is recorded with each invocation, so a CLI update does
  not invalidate earlier reviews. The API credentials of the parent session
  are not passed to the reviewer process; the subscription login is.
- The route limit is 1,300,000 characters of input. The transport elides
  re-delivered and replayed evidence bodies against that limit the way the
  Codex route does; a request that still exceeds it is refused before the CLI
  runs and the refusal is recorded as a failed attempt. The route accepts text
  evidence only.
- `review_transport` dispatches the local adapters through one registry. The
  `openai_responses_v1` adapter is unchanged.

## The problem packet delivers each inspected span once

- Measured on the first problem record: the result packet held 3.37 MB because
  every cited full reading was delivered twice, as its full-text artifact and
  as 2,000-character chunks of the whole-text inspection that makes a reading
  complete, with about nine 64-character hashes per chunk. The same packet now
  holds about 0.5 MB.
- A reading is delivered with its notes and, per inspection, its unit, note,
  offsets and `whole_text`. Each inspected span that does not cover the
  complete text is one inline passage `{reading_id, inspection_index,
  version_id, start, end, text}`. A whole-text inspection is marked and not
  repeated; the full text is held and a reviewer requests it with
  `source_requests`.
- The coverage check verifies each delivered span against the stored source:
  a changed character, shifted offsets or an inspection that does not contain
  the span leaves the reading undelivered. A reading inspected only as a whole
  counts as delivered when the history attached its full text.
- `assessment_evidence` does not repeat a reading that `readings` holds; the
  entry names where it is delivered. An artifact that a material objection's
  stating review received in full is named by reference. A
  `delivery` note in the problem evidence states these rules to the reviewer.
- A source-request turn of a result review names the problem evidence that
  the earlier turn delivered instead of repeating it.

## Result reviews cite delivered records by kind and id

- Each projected record of the problem evidence carries a `cite` object
  `{kind, record_kind, id}`. The version 2 result prompt asks the reviewer to
  copy it, without a digest, and the recording binds the citation to the
  version that the packets delivered. A record kind written with hyphens
  names the kind written with underscores. A present digest is checked as
  before. The bar, slate and adjudicator prompts and their citations are
  unchanged.
- The result prompt also states that `objections` lists only the material
  objections the reviewer raises itself, and that a prior objection receives
  its finding in `objection_findings`.
- An assignment on the 0.55.x result prompt stays verified: that prompt is a
  recognized previous prompt.

## Transport of the local routes

- The packet is labelled as JSON on every route (the Responses API's JSON-mode
  rule). On a text-only route a binary artifact is named without its bytes
  and the omission is stated in the packet; `record_assignment` builds a packet
  for a text-only route with text-only source deliveries.
- A packet that carries problem evidence asks the transport to replay the
  session's earlier turns without evidence bodies longer than 4,096
  characters, without the packets of a scientific history, without the parts
  the current packet repeats, and with each earlier source delivery reduced to
  its request and status. A packet without the marker replays unchanged.
- The Codex route elides re-delivered bodies, the bodies of a scientific
  history and the full texts an openness packet ranks lowest, until the input
  fits the app-server limit of 1,048,576 characters, and then elides the
  bodies of the replayed history from the oldest turn. An input that no
  elision fits is sent as it stands, so that the app-server's refusal is
  recorded as a failed attempt.
- The Codex adapter recognizes the startup declarations of Codex CLI 0.162.1
  and runs at reasoning effort `high`.

## Attempts, context and openness

- A completed attempt whose transport inspection found the context compromised
  at run time is not an observed review: a later observed attempt binds the
  assignment, and the assignment can be invoked again.
- A recorded contamination event on an attempt whose provenance is exact
  leaves the contamination obligation alone, so the context-repair path takes
  over the slot.
- The openness spec accepts `minimum.text_priority`, the versions whose full
  texts a text-limited route delivers first. `problem-openness` records a
  finding whose `coverage` is a nonempty list or object as given. A `web`
  search response names its query under `search_string` as well.

## Route retirement

- `review-context` records `kind: "route_retired"` on an assignment of a
  route, with the owner's instruction as evidence. A retired route accepts no
  new assignment and no run (`review_route_retired`); an assignment on it that
  never produced an observed output is dead and holds no slot; observed
  outputs on it stay verified.
- A retirement is a cause for a context repair, like a contamination: the
  repair names the retirement event, its evidence and a probe of the new route
  recorded after it, and the repair packet carries the cause under
  `context_repair.cause`. A dead continuation on the retired route does not
  block the repair.

## Upgrade effects

- A problem record reviewed on the Codex route under the repaired 0.55.0 copy
  keeps its assignments verified: on the first problem record, 34 assignments
  have the same state, the same evidence digest and the same prompt hashes
  under 0.56.0 as under that copy.
- A result assignment of 0.55.x stays verified on its recognized previous
  prompt. A new result assignment uses the prompt of this release.
- A result packet built by 0.55.x keeps its stored form. The gate compares a
  packet with the evidence as this release describes it, so a result review of
  0.55.x whose packet differs reports `problem_evidence_unassessed` until the
  same reviewers reassess on a packet of this release.
- The local repair T24 of v19 (a slot made replaceable by an author-written
  observation event) is not shipped; 0.55.1's authenticated refusal records
  cover a refused output. A replacement made under that local rule stays as
  recorded history.
