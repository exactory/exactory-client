# Exactory 0.71.1

This patch lets a reader of the research store retry when a writer deletes the rollback journal while the reader
checks it. Before, the reader stopped with `unsafe_path`.

## Why

Before each transaction, the store checks the database file and its journal files by path: each must be a regular
file with one link. When a writer commits, SQLite deletes the rollback journal. A reader whose `stat` of the journal
path came in that moment received the attributes of the unlinked file, with a link count of 0, and the check raised:

```text
unsafe_path: SQLite files must not have aliases outside atomic workspace publication
```

CI of 0.70.2 met this once, in `test_review_task_execution_worker`, where the controller reads the store while the
worker writes its identity. A user could meet it whenever a read runs during another process's commit.

## What changed

`storage.Store._check_files` treats a rollback journal with a link count of 0, seen by `stat` or by `fstat` after
opening, as a journal that its writer is deleting, and checks that path again, at most three times. An absent journal
is accepted as before. A journal that exists must pass every check, and the opened file must now also have exactly one
link. When the journal keeps changing, the reader gets `store_busy` and can retry later.

The database file, the publication window of a new database and every other alias or symlink check are unchanged.

## Upgrade

No action is necessary.

## Checks

New tests in `tests/test_research_storage.py` reproduce the interleaving deterministically (the reader's journal
`stat` returns the attributes of the unlinked journal after the writer commits) and check that an externally
hard-linked journal is still rejected. `test_research_storage`, `test_review_task_execution_worker` and
`test_review_task_execution` pass on Python 3.12.8 and 3.9.6, and without `PYTHONPATH` as CI runs them, together with
the manifest and version tests at 0.71.1, `codex/generate.py --check` and `git diff --check`.
