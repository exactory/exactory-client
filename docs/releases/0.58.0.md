# Exactory 0.58.0

This release ships the repairs that two problem records made in local
runtimes of 0.56.0 on 2026-10-21 and 2026-10-22, and the open tasks of the
harness records that those problems opened. The records are the folders under
`misc/harness-improvement/` of the exactory repository whose names start with
`20261021`.

- The extremal-graph-stability record posted problem 5aa390a0. It ran a
  runtime with the reviewed local repairs v20 to v32 and a posting-gate
  repair.
- The Sidorenko girth-six record posted problem be093644. It ran the local
  runtime `candidate-11`.

Both runtimes are merged with 0.57.0. Where the two runtimes and 0.56.1
changed the same rule in different ways, this note states the rule that
0.58.0 keeps.

## Upgrade effects

- 0.58.0 reads the records that the two local runtimes wrote. Earlier
  releases cannot read a native log with `verified_strategy_obstruction` or a
  public side interval, and they read `objection_identities` as absent.
- The Claude Code and Codex adapters are unchanged, so their recorded attempts
  keep their runtime identity. The runtime identity of an
  `openai_responses_v1` route is the digest of `review_transport.py`, which
  changed. Probe such a route again after the upgrade. Its recorded attempts
  no longer authenticate.
- The `codex_cli_visual_v1` route renders PDF pages with `pdftoppm`.

## Review input on a local route

- A text route fits an oversized request, other than a `complete-visible-v1`
  continuation, with one fixed order of reductions, listed in
  `docs/research-cli.md`. The route withholds the replayed bodies of earlier
  turns first. It tries to defer whole requested sources after it reduces the
  full texts of fully read works and before it reduces any other evidence
  body. Apart from that deferral and an HTML original whose complete extraction
  is delivered, no step withholds the body of a source that the turn delivers
  on request. A body that a step withholds names its delivery and carries a
  note.
- The route withholds the body of an HTML original only when it delivers the
  complete extraction from the same capture, which then stays.
- A continuation whose requested sources do not fit receives whole sources in
  a deterministic batch. The other sources stay pending as `deferred_capacity`
  for the same reviewer. The continuation, the context repair and the final
  gates read that pending state from the actual request.
- The route can also withhold the bodies of the captured responses of a
  problem record's bound searches, of the full texts of fully read works and,
  last, of any other evidence of a problem packet. The last two of these steps
  keep every protected body and every source that the turn delivers on
  request.
- Authentication rebuilds every recorded request. It also accepts a request
  that the order of 0.56.0, of 0.56.1 and 0.57.0, or of either local runtime
  built from the same inputs. A retry repeats the request of its completed
  attempts, and the next phase of a reviewer replays its recorded request.
- A source request of unspecified format is satisfied by one complete,
  validated main representation of the exact version, for example the PDF
  when the HTML capture has visual diagnostics. Required units stay required.
- A PDF that a server declared as `application/octet-stream` is recognized by
  its signature on review delivery, as the extraction already recognized it.
  A text route withholds it, and the Responses route attaches it as a PDF.
- On `codex_cli_v1`, a problem result continuation can set
  `context.source_delivery: "complete-visible-v1"`. For each full text that its
  lineage requested and that is available with its required units, the
  reviewer then receives one complete main text in a visible reversible
  encoding. An incomplete or unavailable request stays pending.

## New review routes

- `codex_cli_framed_v1` at `codex://local` sends the complete UTF-8 evidence
  of an openness packet with screening evidence as numbered blocks of exact
  length and digest. Register and probe it separately.
- `codex_cli_visual_v1` at `codex://local` sends the rendered pages of each
  required PDF inspection as images, with their exact provenance. A problem
  result continuation that uses `complete-visible-v1` on `codex_cli_v1` and
  needs those page images can move its slot once to a verified
  `codex_cli_visual_v1` route of the same model, with the same reviewer,
  author, problem evidence and bars and its complete history.

## Problem result reviews and the post gate

- New result assignments use the version 4 result prompt. Its example writes
  the `stop` assurance as `passed`, and it defines `not_assessed` as an
  assessment that the reviewer could not complete. The version 2 and 3 prompts
  stay verified, and a result on either can be refreshed once for the changed
  contract (`prompt_contract_changed`).
- The post gate counts an unassessed `stop` as passing only for a result on a
  version 2 prompt, whose example wrote it so. 0.56.1 counted it for every
  result.
- Reading coverage of a problem result is checked against the actual request
  that the reviewer received.
- A reference without a digest in the frozen audit names the one version that
  the packets delivered. Two delivered versions, or a legacy projection
  without a digest, name none, and the reference is refused. The refusal
  detail keeps `digest: null`, as 0.56.1 introduced it.
- `review-output-correction` lets the same reviewer relabel as `revised` the
  reassessment findings of a refused result that it labeled `confirmed`
  although their content changed. It runs once per assignment and is not a new
  review.
- The post gate reuses the evaluation of one immutable snapshot and the state
  of identical inputs within one operation. In one read-only reproduction of
  the extremal record's posting decision, the decision took 214 seconds with
  this change. The original decision took 2,096 seconds.

## Objections, context repairs and adjudication

- Two blind reviewers who choose one objection id for different claims keep
  two identities. The later one is recorded as `<id>@<review id>`, with
  `stated_id` in the packets. Findings, versions, adjudications and the post
  gate use the identity.
- A restatement of a delivered objection under its id with another claim is a
  recorded output refusal, so the assignment can run again.
- A context repair labels an inherited review `confirmed` only for an exact
  copy. The repair prompt says so and tells the reviewer to give a prior
  objection its finding instead of restating it. The check reads only what the
  harness delivered, never a reviewer's own earlier output.
- A repair whose two outputs were refused no longer holds the slot.
- A focused problem adjudication can find a material objection `not_binding`:
  its claim holds, but the problem does not rest on the contested premise.
  Such an adjudication resolves the objection. A rubric shortfall still needs
  `not_upheld`. An adjudication on the earlier prompt can be refreshed with
  the reason `protocol_changed`.
- A focused adjudicator receives the complete current source of each full
  reading, because it cannot request a source.

## Openness

- `native_reviews` in the openness spec supplies an observed approving native
  review of a local proof, with the bytes of its analytical dependencies.
- `source_evidence` supplies a captured screening source, whole or as an
  exact span, without reading credit.
- `minimum.text_priority` is documented. Without it, the export warns
  (`review_input_too_large`) when the estimated packet exceeds a registered
  text route's limit.
- An entry of `native_reviews` needs an approving native result with
  `schema_version: 2`.

## Native mathematics

- `verified_strategy_obstruction` is a milestone on the producer's target
  obligation. Its accepted obstruction excludes the producer's admitted
  strategy. It does not obstruct a route.
- `accepted_standalone_claim` accepts a standalone result without root credit.
  `search side-interval` allocates its bounded work under the user's recorded
  instruction.
- The strategy reassessment prompt states that approving a strategy grants no
  proof, openness or closure credit. Its later versions keep the native output
  fields as strings and carry no trailing space.
- `review-run` checks a `native_math` output against the native review shape
  when the run completes. A malformed output is a recorded refusal, and the
  assignment can run again. The receipt names the refusal under
  `output_refusal`. A `revise` or `reject` result needs only its decision and
  a reason. A problem record's openness coverage can still be a nonempty list
  or object.

## Hooks and tools

- The math hook skips a shell token as a path when one of its
  slash-separated components is longer than 255 bytes, since such a token
  names no file. A long `task add` text with a slash made the hook ask for
  recovery.
- When the installed controller cannot replay a record, the hook names that
  controller and says that a record of a newer exactory-math needs a release
  that reads it.
- `exactory-lab probe` runs in a problem record, which has no `study.json`.
- In a problem record, `bundle` warns (`problem_citation_locator_missing`)
  when the work has no DOI, no arXiv id and no HTTPS unit url, before a reading
  binds the bundle.
- A cited PDF page is checked against the page map of the delivered
  extraction. The check had not run for any acquired PDF.

## Not in this release

- A citation of a body that reached the reviewer only in an earlier turn, or
  that a route withheld, still counts as delivered when the frozen packets
  carried it. The actual-request rule needs a design decision first: a
  session replays its earlier turns in compacted form, so that rule can refuse
  citations that the reviewer saw in an earlier turn.
