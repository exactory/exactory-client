# Exactory 0.69.15

This release lets a problem record give a `url:` work its citation title and authors, each bound to the exact bytes of
a retained capture.

## Why

A work that exists only on the web, for example a manuscript PDF in a GitHub repository, enters the store through a
`web` import. For a GitHub code search response, the only title field is the file path, and the response maps no
authors. The exported citation of such a work therefore read `paper/main.tex`, with no authors. No command could correct
it: a later import fills the title and the authors of a work only when they are empty.

The quantum-codes record of math-conjecturer (on 0.69.6) met this defect. Its independent result reviewers kept an
objection open until the citation of a decisive GitHub manuscript gave its authors and its title.

## What changed

- New command `problem-citation-metadata`, payload `{id, version_id, title, authors, year?, evidence}`. It appends the
  immutable record `problem_citation_metadata/<id>` for an existing `url:` work with no DOI and no arXiv identity, which
  a valid full reading of the store covers.
- Each title, author and year string has one evidence span `{kind, source_id, sha256, start, end}`. The span selects
  UTF-8 bytes of the extracted full text of that exact version (`fulltext`) or of a captured response (`response`). The
  selected bytes must equal the string exactly. The record keeps the provenance of every span.
- New refusal codes: `problem_citation_work_ineligible`, `problem_citation_evidence_unbound` and
  `problem_citation_span_mismatch`.
- The citation projection uses the latest record of a version, by `(recorded_revision, id)`, for the citation text. The
  locator does not change. The record is validated again at each projection.
- The problem evidence binding adds `citation_metadata: [{version_id, id, digest}]` when a cited version has a record.
  The result reviewers receive the record in the reading's entry, with its spans, their provenance, an excerpt around
  each span and a `cite` reference of record kind `problem_citation_metadata`. The coverage check of a review requires
  that entry.
- `docs/research-cli.md` documents the command, its refusals, and how the export forms the citation text.

## Upgrade

- A record without citation metadata exports its citations, its evidence digest and its review packets with the same
  bytes as 0.69.14. Recorded reviews keep their standing.
- After a record is added for a cited version, the problem evidence digest changes. Refresh the result reviews so that
  they read the record.

## What stays the same

Readings, bundles, openness findings, the work records, the citation check of manuscripts, the reviewer prompts, the
route-pinned transport and cost modules and `review_state_evaluation.py` are unchanged.

## Checks

With `PYTHONDONTWRITEBYTECODE=1`, the modules `test_research_problem_citation_metadata` (23 tests),
`test_research_problem_citations`, `test_research_problem_cli`, `test_research_problem_delivery` and
`test_problem_result_parts` passed on Python 3.12.8 and 3.9.6, and so did `test_codex`, `test_manifest` and
`test_research_guidance` at 0.69.15. `codex/generate.py --check` and `git diff --check` pass. The full suite runs in CI
on the pull request.
