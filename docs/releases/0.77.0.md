# Exactory 0.77.0

This release closes the path by which a reviewed candidate of math-conjecturer lost its review objections. It
follows 0.76.0. The work is recorded in `misc/harness-improvement/20261105171520-objections-lost-on-area-handoff` of
the exactory repository. GPT 6 Astra at effort `ultra` designed the full fix, and the owner chose this interim rule
on 2026-11-06.

## Why

- A bar or slate objection binds the candidates of its own record only. When the skill moved a candidate to a new
  record of another subject class (Formulation, step 5), or a sibling record took it up, the reviewers of the new
  record never received that objection. Nothing in the new record blocked the post on it.
- A design review found this gap. No record is known to have hit it.

## What changed

- The math-conjecturer skill states one rule for every exploration, in "Exploration": one record holds the
  exploration, and no reviewed work moves between records.
- A new record in another subject class is opened only before the first review request of the original record.
- After that, every candidate stays in the record and is compared on its slate. A selected candidate of another
  class waits for a release whose handoff carries the review objections. No sibling record takes it up.
- The thought-experiment entry, which already had this rule, now refers to it. Formulation, step 5 and the slate
  passages follow it. The `problem-statement` row of `docs/research-cli.md` points to it.
- The regression ledger has an open entry for this gap, because the rule is in the skill text and no command
  enforces it.
- The planned fix carries the objections in code. A command imports the material objections of the source record
  with their evidence, the slate and result reviewers of the new record assess each one, and an unresolved one
  blocks the post. It is designed and recorded, and it is not built in this release.

No code changes, no stored record changes, and no migration is necessary.
