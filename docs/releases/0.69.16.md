# Exactory 0.69.16

This patch closes two more defects of the manuscript citation check, which the independent review of 0.69.14 found.

## Why

- Directive heads without a key, such as `@comment{...}`, `@string{...}` and `@preamble{...}`, were not boundaries. A
  line `@misc{fake,title={Recorded paper title}}` inside such a directive therefore became an entry and cited the work
  titled "Recorded paper title". A bibliography that held only such directives was read again as plain text, which
  restored the ignored text as evidence.
- The limit on combining marks of 0.69.14 ran before decomposition. U+0F73 has combining class 0 but decomposes into
  combining marks, so 32,000 of them still took about 1.1 seconds in a title, a URL host or plain text. In a URL host,
  `urlsplit` removed `:` before normalization and joined the limited runs.

## What changed

- Every directive head, with or without a key, is a boundary. `@comment`, `@string` and `@preamble` consume their group
  and create no entry. Another head creates an entry only when a key and a comma follow it; without a key it still
  consumes its group.
- A bibliography with at least one directive head is BibTeX, even when it has no entries, and is never read again as
  plain text. Only a bibliography without any head is read as plain text.
- A title is normalized by decomposing each character on its own. Combining marks are dropped as before, so the result
  is the same for every title, and the time is linear. No run of combining marks is cut any more.
- A URL whose authority holds a character outside ASCII names nothing and is not parsed. The registry hosts are ASCII.
  The authority is checked before any casefolding.

## Upgrade

- Text inside `@comment`, `@string` and `@preamble` is never evidence, also in a bibliography that holds nothing else.
- A title or a URL with a long run of combining marks keeps all of its marks.
- The notes on BibTeX keys (since 0.69.8), on DOIs in publisher URLs (since 0.69.10), on Markdown link texts (since
  0.69.11), on head-like lines in parenthesized entries (since 0.69.14) and on `already_cited` items (since 0.69.5)
  still apply. Publication bundles that are already recorded do not change.

## What stays the same

The field reading, title matching, `find_citation_tokens`, the problem citation projection and the
`problem-citation-metadata` command of 0.69.15, the reviewer prompts, the route-pinned transport and cost modules and
`review_state_evaluation.py` are unchanged.

## Checks

The new tests ran first against 0.69.14 and failed as expected (54 failures). One existing expectation changed: a URL
with a long run of combining marks is no longer cut, so it no longer matches the shortened DOI. After the change, with
`PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=tests`, the modules `test_research_citation_accounting`,
`test_research_problem_citations`, `test_research_providers`, `test_research_publication`,
`test_research_publication_records`, `test_research_publication_files`, `test_research_problem_delivery` and
`test_math_problems_cli` (397 tests) passed on Python 3.12.8 and 3.9.6. The new performance cases took at most 0.07
seconds. `codex/generate.py --check` and `git diff --check` pass.
